## 0. 结论先行

- **它是什么**：一个 Rust + GPUI 的原生多引擎数据库客户端，用「无 Electron/JVM + 原生渲染 +
  流式结果 + 虚拟滚动」把启动、内存、百万行滚动做到与 DBeaver/Navicat 的代差；
  同时用一套**极严格的 SQL 信任模型**（不改写用户语句、生成 SQL 白名单、写前审阅、事务内回读校验）
  解决「GUI 改数据不放心」这个行业老问题。
- **真正的护城河不是功能数量**，而是三件事同时成立：
  1. **速度**：1.13s 冷启动、133MB 空闲内存、1,000 行 0.21s、100 万行 55.6s（`BENCHMARKS.md`）；
  2. **信任**：用户 SQL 原样执行，行数上限靠「只保留 N 行并停止读取」而不是注入 `LIMIT`；
  3. **信息透明**：执行计划、行检查器、结构页、状态栏都在回答「这结果是什么、从哪来、完不完整」。
- **DB Studio 最该学的三件事**：
  1. **行检查器**（当前行完整阅读/编辑）——补上宽表「只能横滚 + 逐个弹窗」的短板；
  2. **执行计划可视化 2.0**——把「表格里读数字」升级为「一眼看出最慢节点/全表扫/估算偏差」；
  3. **导入向导的 SQL 预览与空值语义**——把「写前可见」从网格延伸到导入，并守住 NULL/空串保真红线。
- **DB Studio 明确不该照搬的三件事**：
  1. ER 图、29 套主题/玻璃、11 引擎广度——与单机、MySQL 优先、单一设计语言的定位冲突；
  2. 无主键「全列匹配 + 恰好一行」可编辑、Row 模式离开行即自动保存——直接违反 DB Studio 两条红线；
  3. 整表文本化与全量结果常驻——DB Studio 的列式 ArrayBuffer + 只解可视区是更正确的内存路线。
- **一句话**：DBDelve 证明「原生快 + SQL 可信」可以同时做到；DB Studio 应学它的**信任可见化**与
  **信息层级**，而不是学它的功能广度与视觉花样。

## 1. 项目画像

也决定了它不适合被当成「照着抄一遍」的模板。

**分析局限**：本次没有安装并运行 DBDelve 安装包，界面结论来自源码 + 官方截图 OCR/分区还原，
因此「手感/动画/真实帧率」只能引用作者 benchmarks，不能当作独立实测；仓库为浅 clone
（单 commit 快照），也无法评估协作历史与 issue 响应。后续若要立 P0 项，建议在本机安装
同版本做一次 30 分钟任务对照（连接→定位表→改一格→看计划→导入 CSV），再定验收数字。

## 2. 优点与核心特长

### 2.1 性能：不是口号，是架构的结果

- **原生渲染**：GPUI 直接画，省掉 Electron/Chromium 的运行时与 DOM 成本；依赖在 dev profile
  也开优化，因为文本布局/字形整形每帧都在 CPU 上跑（`AGENTS.md`「Stack」）。
- **流式读取**：结果边到边进网格，首行约 0.1s 出现；不是「查完再渲染」。
- **文本协议 + 紧凑行包**：服务端已把值格式化成文本，客户端只搬字节；`Row` 用 `Box<str>` +
  每格 `u32` 尾偏移，NULL 用最高位标记（`src/db/mod.rs`），避免「每格一个堆块」。
- **双轴虚拟化**：只渲染可视区 + 缓冲；滚动路径不做对象分配。
- **列宽只按前 200 行拟合且只增不减**：避免滚动时列宽抖动，也避免全量扫描。
- **可量化**：`BENCHMARKS.md` 给了机器、表、方法、5 次中位数；1,000,000 行 × 107 列
  55.6s / 4.9GB，释放后 344MB。

> **注意**：4.9GB 是「关闭行数上限、整表拉进内存」的极端数字，不代表日常浏览。
> 它的「省内存」主要指空闲 133MB；DB Studio 的列式传输体积并不更小，但「只解可视区」
> 让渲染端内存有界。两者不是同一条路线，不能只拿一个数字对比。

### 2.2 SQL 信任模型：最值得 DB Studio 研究的部分

DBDelve 的硬规则写得很清楚（`AGENTS.md` 硬规则 1-3、`docs/agents/gates.md`）：

1. **绝不静默改写用户语句**：不注入 `LIMIT`、不做列投影、执行时不重排格式；
   行数上限只决定「保留多少行」，不改变发出去的 SQL。超限时停止读取，并在 UI 明说
   `1,000 rows, stopped at limit`（`src/workspace/mod.rs:2145-2190`）。
2. **生成 SQL 走白名单门禁**：网格写只允许固定形状（单行 UPDATE/INSERT/DELETE、
   列 = 字面量、可识别的 `BEGIN/COMMIT` 等）；门禁**从语法树回读形状**，不信任生成器
   的自我声明（`src/sql.rs:1213`、`1629`）。
3. **危险操作分层**：连接三档 `Read-only / Read-write / Full`，按 `required <= allowed`
   判定；`DROP/TRUNCATE/无 WHERE DELETE/不可解析语句` 单独标记；不可解析语句必须确认后
   「只跑一次」，且不会因为「想要语法错误」就把用户训练成常驻 Full（`src/sql.rs:3344` 起）。
4. **写前审阅 + 事务内校验**：网格草稿逐条展示 SQL；在支持验证的引擎上，提交时在事务内
   重读行、逐条计数、失败回滚（`docs/agents/gates.md:99-159`）。
5. **永不写 `DROP/TRUNCATE` 到 buffer 或线上**；`DELETE` 只以「命名一行」的形式生成，
   `WHERE` 必须能唯一定位。

**对 DB Studio 的映射**：DB Studio 已有「只提交脏单元格 + 逐条预览 + 冲突检测 + 无主键只读」，
与 1/4/5 重合；真正可借鉴的是 **2 的「从 AST 回读形状」** 和 **3 的「风险分级可见化」**。
不要照搬「不可解析语句确认后放行」——DB Studio 的 guard 要求闭合枚举、解析失败即拒，
这是更严格也更适合自用工具的取舍。

### 2.3 编辑安全：把「敢不敢改」做成产品能力

- 单元格脏标记、逐条 SQL 预览、批量草稿、失败保留脏标记；
- 无主键表：DBDelve 在部分引擎允许「全列匹配 + 恰好一行」编辑，DB Studio 明确禁止（红线 2），
  这是两套不同的风险偏好；**不要因为 DBDelve 做了就动摇 DB Studio 的红线**；
- Row 模式（离开行即保存）是 DBDelve 的便利功能，但与 DB Studio「任何写操作必须先预览」
  的红线冲突；**不采纳**；
- 真正可借的是「**Apply 弹窗里能逐条展开/折叠 SQL**」与「**失败后保留草稿**」的交互细节。

### 2.4 键盘优先：不是堆快捷键，而是「每个面都有路径」

- 115 条动作注册、69 条默认键、46 条可后续绑定；支持多段 chord（如 `⌘K S`、`⌘K W`）；
- 作用域（context）与冲突检测是**代码 + 单测**：`contexts_overlap`、`no_shipped_default_collides_with_another`
  （`src/keybindings.rs:326-333`、`486-498`）；
- 命令面板 6 个 scope：All / Commands / Objects / Queries / History / Connections；
  `⌘P` 直接进 Objects，`⌘⇧P` 进 Commands，点标题栏连接进 Connections；
  `Tab/⇧Tab` 换 scope，`←/→` 只在光标到端点时换（`src/palette.rs:92-138`、`1492-1504`）；
- 每个 palette 行都是 `Command`，`run_command` 一对一转到按钮/快捷键已用的方法，
  不做第二套实现（`docs/agents/ui.md:55-61`）；
- Esc 有栈：先关菜单/补全，再还焦点，最后 propagate；面板/模态关闭后必须把焦点交回，
  否则整个键盘失效（`docs/agents/ui.md:42-53`）。

**对 DB Studio**：DB Studio 已有动作目录（单一事实源）与只读快捷键速查，基础比 DBDelve 更规范；
缺的是 **scope 化面板** 与 **「当前可用动作」的提示**，不是再抄一份键位表。

### 2.5 信息设计：让「结果」自己解释自己

- **执行计划**：树形节点 + 固定宽度条形（self time 占比）+ 最慢节点高亮 + `actual / est /
  ×N misestimate` 并排 + `Filter` 的 SQL 高亮（`src/views.rs:440-663`）；
- **行检查器**：`Row 9 of 1,000`，按列名/值过滤字段，类型小字，NULL/DEFAULT 区分，
  JSON 美化高亮，长文本编辑，字段级复制（`src/views.rs:77-156`、`2090-2530`）；
- **结构页**：Columns / Indexes / Foreign keys / Checks / Partitions 分区，只读、可复制、
  跳数据；空分区不显示（`src/structure_grid.rs:26-68`）；
- **状态栏**：`Sort Server|Client`、列数、`1,000 rows, stopped at limit · 4.0 MB · 126.9ms`、
  导出进度、未提交改动、Apply/Discard（`src/workspace/mod.rs:2306-2530`）；
- **表体积/陈旧标记**：侧栏表行显示 `3.1 GB`，schema 过期显示 `structure stale`；
- **ER 图**：卡片=表、边=外键，Sugiyama 分层、LOD、minimap、查找、导出 SVG/PNG/Mermaid
  （`src/diagram/`、`src/diagram_view.rs`）——视觉上很强，但 DB Studio 明确不做 ER 图。

### 2.6 上手与多环境：把「危险」和「陌生」都可视化

- Welcome 页：粘贴连接 URL、按引擎平铺、New project、从 DBeaver/TablePlus 导入、主题、设置
  （`src/workspace/welcome.rs:315-370`）；
- 连接表单分三组 `CONNECTION / SECURITY / BEHAVIOUR`，含 Test、颜色、项目、语句超时；
  模式只在创建时可选，编辑不改模式（`AGENTS.md`「Connection modes」）；
- 连接颜色可染标题栏；连接行有状态点、host、数量；项目在 palette 的 Connections 树里分组；
- 导入连接默认 Read-only、去重、先问项目（`src/workspace/profiles.rs:1858-1945`）。

### 2.7 工程纪律：可证伪、可回归、可解释

- 3,269 个测试函数；e2e 用真实 `Workspace` + 生产 keymap + `simulate_keystrokes`，
  不是「直接调 handler」；
- CI：Linux 跑 fmt/clippy/nextest（含真库 live、插件、ODBC），macOS/Windows 跑 clippy+test；
  另有 cargo-deny、zizmor、Windows 更新器 e2e；
- 性能预算写成 release-only ignored 测试（布局 50ms、帧 8ms、1000 表布局上限）；
- 日志有「绝不写查询文本/结果/密码/连接串」清单（`src/logging.rs`）；
- 更新器先验 `.minisig` 再下载，按平台原子替换；
- `docs/agents/` 是「每个区域怎么改、为什么」的活文档，而不是一次性设计稿。

**最值得抄的不是工具链，而是三条习惯**：
1. 非平凡逻辑留一条「最小可运行检查」，且先在错误实现上确认它会红；
2. 门禁验证解析树，不验证生成器的口头承诺；
3. 删除优于新增，不做「只有一个实现的 trait/工厂」。

## 3. 缺点、风险与「产品取舍」

| 问题 | 事实/证据 | 对 DB Studio 的含义 |
|---|---|---|
| **GPL-3.0** | `Cargo.toml:7` | 只能学设计，不能复制代码/资源；DB Studio 是 MIT |
| **体量与维护** | `src/` 253k 行；`sql.rs` 11.8k、`result_grid.rs` 9.6k、`e2e.rs` 21.2k；单 crate | 不要模仿「巨型文件」；DB Studio 应保持 `core-*` + 小模块 |
| **GPUI 预 1.0 + vendor** | 5 个 vendored crate，精确 pin，升级需手工重放 patch（`Cargo.toml:473-514`） | 技术选型要算升级税；Electron 44 的锁定同样是税，但生态更稳 |
| **无表设计器/结构编辑** | `structure_grid` 只读；routine 只读 | DB Studio 的表设计器是领先项，不要为了「像 DBDelve」而砍掉 |
| **无障碍/i18n 弱** | 源码几乎没有 a11y 角色/标注；ER 是 canvas；UI 硬编码英文 | DB Studio 的中文界面与「所有图标按钮有 aria-label/title」规范是优势，继续保持 |
| **发现性差** | 46/115 动作无默认键；Server/Client 排序、Edit 模式藏在状态栏；窄窗先裁 Sort | 状态栏信息要分层/可折叠，不要学「把关键开关埋起来」 |
| **文本化整表** | 1M 行 4.9GB；排序/统计只能回服务端或重新解析 | 不要退回字符串二维数组；列式 + 只解可视区更优 |
| **MySQL 单连接串行** | 一条长查询会挡住同连接 catalog 读取（`mysql.rs` 注释自承） | DB Studio 也需明确「查询连接」与「元数据连接」的隔离 |
| **MySQL 影响行数解析** | 从 OK 包 info 文本按位置解析 matched 数，依赖 `lc_messages` 不变 | DB Studio 应优先用驱动结构化字段，不解析人类文本 |
| **取消只有「已请求」** | UI 显示 Cancelling，但无服务端回执 | DB Studio 已有 KILL + processlist 验收，保持 |
| **快照静默截断** | 重启恢复只保留前 5,000 行（`GRID_ROW_CAP`，`store.rs:39`） | 若做结果快照，必须显式标「capped/前 N 行」 |
| **单窗口** | 关窗即退出 | DB Studio V23 多窗口是差异化，不必学 |
| **ER 图鼠标依赖** | 平移/缩放/拖拽、hover 才出现的复制按钮 | 非目标；若未来做，先补键盘路径 |
| **解析边界** | JIT 行错挂、`" on "` 切词误判表名、自绘解析器覆盖有限 | DB Studio 的 MySQL JSON 路径更窄，但也要准备降级 |

> **重要区分**：上表有些是「产品取舍」而非缺陷。例如无表设计器、无 BI、无多窗口，
> 都是 DBDelve 为「快/小」主动放弃的；DB Studio 不应因为竞品不做就跟着不做，
> 也不应因为竞品做了就盲目补。

### 4.2 关键模块与职责

| 模块 | 职责 | 可借鉴点 |
|---|---|---|
| `db/spec.rs` + `db/target.rs` | 把引擎差异做成**数据**（引号、分页、布尔字面量、只读能力、Hooks）；UI 问 `Target` 的能力，不问引擎 | 未来加 PostgreSQL 时，先做 `EngineSpec/Abilities`，避免每个 view 里 `if (engine === 'pg')` |
| `db/mod.rs` | 闭 enum `Connection`，每个引擎一个 arm；驱动类型不越过 `src/db/` | 新增引擎时编译器逼你补全所有决策；代价是近十处改动 |
| `sql.rs` | 语句边界（tree-sitter）、风险分类（sqlparser）、生成 SQL 白名单、行定位、删除/更新生成 | 「门禁从 AST 回读」比「相信生成器」强一个数量级 |
| `session.rs` + `workspace/queries.rs` | 每 tab 的查询状态、队列、取消、结果槽、排序/limit/offset | 查询与 catalog 分离；取消走独立线程，不排在阻塞池后面 |
| `result_grid.rs` | 行包、列宽拟合、选择、编辑、复制、虚拟渲染 | 行包/尾偏移、列宽只增不减、前 200 行拟合 |
| `palette.rs` + `keybindings.rs` | 6 scope 面板、单一 fuzzy matcher、动作注册、冲突检测 | scope 切换 + 键帽提示 + 「动作只实现一次」 |
| `views.rs` | 行面板、计划视图、工具栏、状态栏布局 | 计划条形/错估、行面板的字段过滤与类型标注 |
| `structure_grid.rs` | 结构分区（列/索引/FK/检查/分区），只读 | 分区 chips、空节不显示、表达式 SQL 高亮 |
| `import_dialog.rs` | 格式选项、列映射、逐列 Parse as、空字段语义、Rows/SQL 预览 | 导入的「写前可见」与 NULL/空串保真 |
| `store.rs` | `profiles.toml`、钥匙串、历史、grid 快照（5,000 行上限） | 快照 capped 语义、损坏文件移走、未知 profile 保留 |
| `diagram/` + `diagram_view.rs` | ER 图布局（纯几何）与 canvas 渲染 | 纯函数布局 + LOD + 视口裁剪；但产品面不适合 DB Studio |

### 4.3 数据流（从连接到屏幕）

```text
连接配置 → Target(Engine+Driver) → 建立会话/隧道
  → catalog 读取（内存，不落盘）→ 侧栏/补全
  → 用户 SQL / 生成预览 SQL
  → 驱动流式读取 → 行包（文本 + 尾偏移）
  → 网格只解码/渲染可视区
  → 编辑：脏单元格 → 生成 SQL → 门禁（AST 回读）→ 预览 → 事务提交/校验
  → 状态栏：行数/字节/耗时/是否截断/快照年龄
```

### 4.4 与 DB Studio 的架构映射

| DBDelve | DB Studio | 备注 |
|---|---|---|
| `src/db/*` | `packages/core-driver-*` + `core-sql-guard`/`core-mutation` | DB Studio 的包边界更利于单测 |
| `src/sql.rs` | `core-sql-guard` + `core-mutation` + `core-sql-ident` | 不要合并成巨型模块 |
| `src/session.rs`/`workspace` | `apps/desktop/src/main` + renderer `workspace/` | DB Studio 的 App.tsx 仍偏大，可局部抽取 |
| `src/result_grid.rs` | `core-grid-view` + `DataGrid.tsx` + `core-ipc-codec` | DB Studio 列式传输更优，保留 |
| `src/palette.rs`/`keybindings.rs` | `core-command-palette` + `shared/action-catalog.ts` | DB Studio 的动作目录已是单一事实源 |
| `docs/agents/*` | `docs/engineering` + `docs/design` + `AGENTS.md` | DB Studio 文档纪律不弱，继续保持 |

## 5. 交互方式、界面分区与按钮布局

### 5.1 窗口分区（单窗口，约 2000×1250 截图口径）

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 品牌 │ 项目 │ 连接 ▾ │ 数据库 ▾ │ schema ▾ │ 刷新 │ 模式 pill │ 更新 │ 设置 │
├───────────────┬──────────────────────────────────────────────┬───────────────┤
│ 对象过滤      │ 标签条（Query / 表 / 结构 / 图）              │ 行检查器       │
│ New Query     ├──────────────────────────────────────────────┤ Row 9 of 1,000│
│ 连接/库/表    │ 编辑器 或 表数据                              │ Filter...     │
│ 表/视图/函数  │ 过滤条 / 工具栏                               │ 字段 1 ...    │
│ 表体积        │ 结果网格                                      │ 字段 2 ...    │
│               │                                               │ JSON / 长文本 │
├───────────────┴──────────────────────────────────────────────┴───────────────┤
│ 状态栏：Sort Server|Client │ 列数 │ 行数/字节/耗时 │ 导出/复制 │ 未提交改动   │
└──────────────────────────────────────────────────────────────────────────────┘
```

- **左侧栏**默认 220px（180-480 可拖），折叠时整条不画；栏底自带 32px 状态行。
- **编辑/结果区**垂直可拖（默认 420/360，最小 120/100）。
- **行检查器** 300px（200-900 可拖），折叠状态按 tab 记忆。
- **状态栏** 32px，无内容时整条不画；notice 独占上方一行，成功 3s 消失、失败常驻。
- **设置**是右侧 440px 停靠面板，与主区并排，不是全屏页面。

### 5.2 标题栏与身份

- 自绘 40px 标题栏，macOS 预留 78px 交通灯安全区；
- 从左到右：品牌 → 项目 crumb（有项目时）→ 连接 crumb（点开 Connections scope）→
  数据库 → schema → 刷新 → **模式 pill**（绿 Read-only / 黄 Read-write / 红 Full，点击下拉）→
  更新提示 → 设置；
- 连接颜色会染标题栏；连接行有状态点、host、对象数量；
- 这是「**我在哪、我能写吗**」的常驻答案，比把只读状态藏在设置里更安全。

### 5.3 标签模型

- `Tab = Query(id) | Object(id)`；Query 与 Object 各带自己的 editor/grid/结果/plan/队列/排序/limit；
- **关系对象有两个独立 tab**：Data 与 Structure（不是三态切换）；Query tab 才有 Data/Plan 成对；
- 同一张表不同 filter = 两个 tab（去重键含 filter），tab chip 挂 filter 文本；
- 未命名 query 依次 `New Query` / `New Query 2`；
- 关闭保护只针对未应用单元格编辑/草稿/行面板未提交文本；`⌘W`、中键、`×` 同走一个
  `ask_before_close`；
- 拖拽按中点 50% 判落位；只有前台连接的 chip 可拖（跨连接拖拽未实现，源码有 ponytail 注释）。

**与 DB Studio 的差异**：DB Studio 的表标签是「Data + 设计器模态」，没有独立 Structure tab；
这既是差距（见 DB-04），也是优势（设计器更强）。

### 5.4 工具栏按钮布局

**Query tab（从左到右）**：
`Hide/Show results` → `Data | Plan`（有 plan 才出现）→ 弹簧 → 命名输入 240px + 确认 →
`Insert in X` → `Rename/Save` → 行数上限下拉（No limit / 100 / 1k / 10k / 100k / Custom…）→
`Explain` 下拉（Explain / Explain Analyze）→ **Run（唯一反色主按钮）**。

**Relation tab（右上）**：
`Data | Structure` 分段 → `Insert`；数据区上方是过滤条（AND/OR、Add filter、clear）。

**状态栏右侧**：
`Copy Results` / `Copy Results As`（TSV/CSV/Markdown/Unicode/ASCII）/ `Export CSV…` /
`Export JSON…` / `Export SQL…`；有未提交改动时出现 `Discard / Apply` 与 `←/→` 逐条导航。

**DB Studio 对照**：DB Studio 工具栏同时放了 Save、刷新、筛选、导出、导入、设计、粘贴、
行高下拉、主题下拉、定位策略、行数/耗时、环境标签。功能齐全但视觉噪声大；
建议保留「身份 / 保存 / 筛选 / 导出」常驻，把行高/主题下沉到偏好设置或「更多」，
这与 DBDelve「工具栏只放当前对象的动作」的原则一致（见 DB-11）。

### 5.5 状态栏：把「当前对象」做成控制台

- 左：`Sort Server|Client`、隐藏列数/Show、列数、Count、导出进度；
- 中：分页（仅可翻页的关系预览出现）；
- 右：`1,000 rows, stopped at limit · 4.0 MB · 126.9ms`、Refresh…、Import 菜单、
  Export 菜单、未提交改动与 Apply/Discard；
- 快照恢复时显示 `snapshot from 3m ago`，而不是伪造 `0 B · 0.0ns`；
- 窄窗先裁 Sort；notice 失败常驻、成功 3s 消失。

**可借鉴**：状态栏是「结果完整性/性能/写状态」的唯一控制台；DB Studio 当前把
行数/耗时放在工具栏、截断提示放在结果 tab，信息是分散的（见 DB-06）。

### 5.6 行检查器（Row Inspector）

- 标题 `Row 9 of 1,000` / `New row`；右侧铅笔（编辑模式）、折叠、关闭；
- 第二行 `Filter columns and values…`，按列名或值过滤字段；过滤状态跨行保留；
- 每字段：列名（当前列 accent）+ 右上类型小字 + hover 复制（150ms 对勾）；
- 值区等宽字体；JSON 语法高亮；NULL 斜体 faint；DEFAULT 单独词；超长值截到 4,000 字符；
- 编辑模式每字段带 `NULL / Empty / DEFAULT` 芯片；
- 面板宽度/折叠按 tab 记忆，不跨 tab 污染。

**这是 DB Studio 最值得补的一块**：右侧详情面板目前是「表信息/字段/DDL」，
单元格完整值要开 `CellValueModal`；在 100+ 列宽表里，用户无法「一屏纵读一行」。
DB Studio 已有 `JsonTreeView`、`TextValueEditor`、`ImageViewer`，复用成本低于从零做。

### 5.7 命令面板

- 6 scope：All / Commands / Objects / Queries / History / Connections；
- `⌘P` Objects、`⌘⇧P` Commands、无默认键的 SearchEverything=All、点标题栏项目/连接=Connections；
- `Tab/⇧Tab` 换 scope；`←/→` 只在光标位于端点时换，避免抢走输入框光标；
- 单一 fuzzy matcher + 命中高亮；All 每组只 5 行；行高 40px、组头 28px、虚拟列表；
- 行 = 图标 + 名称 + 细节 + hint + 键帽 + hover 动作按钮；History 多一排 Status/Sort；
- 每行是 `Command`，执行走 `run_command` 同一实现；删除走单行 Confirm。

**DB Studio 当前**：`⌘K` 面板支持表 / 命令 / 历史三模式，历史支持星标/删除；
缺 **Connections scope** 与 **scope 切换**（见 DB-05）。不要照搬 `⌘⇧P` 键位，
DB Studio 的 `⌘K` 已形成肌肉记忆。

### 5.8 对话框与表单

- 连接表单三组卡片：`CONNECTION`（URL/Name/Host/Port/Database/User/Password）/
  `SECURITY`（Encryption/SSH tunnel）/ `BEHAVIOUR`（Color/Project/Statement timeout）；
  底部 `Test / Cancel / Save`；模式只在创建时选；
- 导入：左侧格式选项（CSV/TSV/JSON、首行 header、分隔符、引号、跳过行、编码、
  空字段语义、NULL 文本、逐列 Parse as），中间列映射，右侧 Rows/SQL 预览；底部
  `Cancel / Import N rows`；
- 设置：左侧导航 + 搜索；Shortcuts 页按 context 分组，每行 `Edit` 捕获新键，
  显示 `Press any key… (Esc to cancel)`；改键重启生效；
- 新建项目/重命名项目是行内命名，不是独立模态。

### 5.9 焦点与键盘可达性

- 焦点是「按键能否到达」的前提：没有焦点就没有 dispatch path，所有键位失效；
- 关闭模态/面板必须把焦点交回；`Focus::Window` 是「没有可输入元素」的兜底；
- Esc 是栈式：先关菜单/补全，再还焦点，最后才 propagate；
- 面板的箭头绑定必须挂在比输入框更深/更精确的 context，否则会被输入框吃掉；
- DBDelve 也有明显不足：46 条动作无默认键、部分控件只在 hover 出现、状态栏开关窄窗被裁。

## 6. 快捷键：值得学的是「分层」，不是具体键位

### 6.1 DBDelve 代表性默认键位

| 类别 | 键位 / 动作 |
|---|---|
| 全局 | `⌘⇧P` Command Palette · `⌘P` Go to Object · `⌘T` New Query · `⌘W` Close Tab · `⌘S` Apply Edits · `⌘,` Settings · `⌘.` Cancel |
| 刷新 | `⌘R` Refresh Rows · `⌘⇧R` Refresh Schema |
| 视图 | `⌘J` Toggle Results · `⌘⇧I` Row Panel · `⌘⇧E` Row Edit · `⌘⇧D` Data/Structure · `⌘⇧S` Sidebar |
| 连接/标签 | `⌃Tab` / `⌃⇧Tab` 标签 · `⌃\`` / `⌃⇧\`` 连接 · `⌘K W` Close All |
| 查询编辑器 | `⌘↵` Run · `⌘⇧↵` Explain · `⌘⇧F` Format · `⌘/` Comment · `Tab` Accept Completion · `⌃Space` Show Completions |
| 数据网格 | `Enter` Edit · `⌘C` Copy · `⌘⌫` Set NULL · `⌘V` Import from Clipboard · `⌘S` Apply |
| 面板 | `↑↓` 选择 · `Tab/⇧Tab` 换 scope · `←/→` 端点换 scope · `⇧↵` 行动作 · `⌘K F` 历史状态 · `⌘K O` 历史排序 |
| 对话框 | `↵` 选中按钮 · `Space` 勾选 · `←/→` 换按钮 |

### 6.2 机制层面的可取之处

1. **动作注册表是唯一事实源**：id 稳定、默认键/context 集中，改键只存 override；
2. **冲突可测**：默认键互不冲突、跨 context 是否重叠、改键后是否与别的动作撞车，都有单测；
3. **多段 chord**：`⌘K S`、`⌘K W` 这类「前缀 + 字母」适合把低频动作塞进不占主键位的空间；
4. **scope 化**：同一键在 Grid / Editor / Palette / Dialog 有不同含义，靠 context 而不是全局拦截；
5. **改键页可发现**：按 context 分组，显示「未绑定」与「Press any key…」，比写死在文档里强。

### 6.3 对 DB Studio 的建议

- **不要改** `⌘K`（面板）、`⌘R`（执行）、`⌘S`（保存预演）、`⌘T`、`⌘W` 的既有肌肉记忆；
- 可补：`⌘P` 作为「对象」scope 的别名（与 `⌘K` 不冲突，且是 DBDelve/VS Code 的惯例）、
  `⌘⇧P` 作为「命令」scope 的别名；
- 可补：面板底部键帽提示（当前可用动作），让「有键位但没人知道」不再发生；
- **暂不做可重绑定**：DB Studio 已有只读速查 + 动作目录；重绑定要同步原生菜单、
  CodeMirror、网格局部 keydown，成本高、单用户收益低（见 DB-14）。

## 7. 信息图形化：哪些值得迁移

| 图形化 | DBDelve 做法 | 对 DB Studio 的价值 | 迁移建议 |
|---|---|---|---|
| **执行计划** | 树 + 72px 条形（self/total）+ 最慢节点 danger 底 + `actual/est/×N` 并排 + Filter SQL 高亮 + 复制原文 | ★★★★★ 直接服务「这条 SQL 慢在哪」 | **优先做估算版**：用现有 `EXPLAIN FORMAT=JSON` 的 `rows_examined_per_scan`/`filtered`/`cost_info` 做条形与告警；`EXPLAIN ANALYZE` 后置（会执行查询，需确认） |
| **行检查器** | 当前行全字段纵读、过滤、类型、NULL/DEFAULT、JSON 高亮、字段复制、编辑芯片 | ★★★★★ 宽表阅读/编辑的核心缺口 | **优先做**：复用现有详情面板 + JSON/文本组件；编辑仍走脏单元格与预览 |
| **结构页** | Columns/Indexes/FKs/Checks/Partitions 分区，只读、可复制、跳数据 | ★★★★☆ 不打开设计器即可看索引/FK | 用现有 designer 的读取结果做只读渲染；编辑跳设计器 |
| **状态栏统计** | 行数/字节/耗时/截断/快照年龄集中 | ★★★★☆ 结果完整性透明 | 小成本；把现有 rowCount/queryMs/truncated 合并并加 bytes |
| **表体积/陈旧** | 表行显示 3.1GB；schema stale | ★★★☆☆ 快速定位大表/知道缓存过期 | 懒加载 + `information_schema` 估算，标「约」 |
| **ER 图** | Sugiyama、LOD、minimap、查找、导出 | ★☆☆☆☆（DB Studio 非目标） | **不做**；最多借鉴「纯函数布局 + 视口裁剪」的工程思路 |
| **主题/玻璃** | 29 套 + glass + Zed/VS Code 导入 + 对比度测试 | ★☆☆☆☆（单主题设计） | **不做**；但可借鉴「token 对比度单测」 |
| **导入预览** | Rows/SQL 双视图、逐列 Parse as、空字段 NULL/空串 | ★★★★★ 写前可见 + 保真 | **优先做**（见 DB-03） |

**执行计划的正确姿势（针对 MySQL）**：
- 第一阶段只用 `EXPLAIN FORMAT=JSON`，**不执行**查询；从 `query_block`/`nested_loop`/`table`
  取 `access_type`、`rows_examined_per_scan`、`rows_produced_per_join`、`filtered`、
  `cost_info.prefix_cost`；用 `rows_examined` 或 cost 占比画条形，标 `ALL` 红、
  `Using filesort/Using temporary` 黄；
- 第二阶段再加 `EXPLAIN ANALYZE`：**只对单条 SELECT**、按钮明确写「会执行查询」、
  走只读 guard、结果按 TREE 文本解析；解析失败降级为原文 + 表格；
- 不要为了「像 DBDelve」而把用户语句改写成 `EXPLAIN` 后丢失原注释；始终保留原文复制。

## 8. 工作流与典型使用场景

### 8.1 五条核心工作流

1. **首次连接 → 看数据**
   Welcome 粘贴 URL / 选引擎 → 表单 Test → Save & Connect → 侧栏过滤表 → 打开 Data →
   行数上限/过滤/排序 → 看到首行。目标：30 秒内完成。
2. **改一个单元格**
   双击/Enter 进入编辑 → 输入 → Enter 标脏（左侧色条 + 背景）→ `⌘S` 弹 SQL 预览 →
   逐条展开 → Apply → 状态栏回执 → 脏标记清除；失败保留草稿。
3. **写 SQL → 排错**
   `⌘T` 新查询 → 输入/补全 → `⌘↵` 执行（可取消）→ 结果 tab → `⌘⇧↵` Explain →
   看最慢节点/全表扫/估算偏差 → 调整 → 导出/复制。
4. **导入 CSV**
   选文件 → 自动探测编码/分隔符/header → 列映射 → 逐列 Parse as / 空字段语义 →
   Rows/SQL 预览 → 校验问题行 → Import N rows（进度/取消）。
5. **切环境/防误操作**
   项目/连接分组 → 颜色/模式 pill → 只读连接 → 危险操作二次确认/输入表名 →
   状态栏「可写/只读」常驻。

### 8.2 典型场景

- **开发库快速修数据**：打开表 → 过滤到目标行 → 改一格 → 预览 → 提交；DBDelve 的
  行检查器让宽表不必横滚。
- **生产只读排查**：只读模式 + 颜色标题栏 + 危险确认；查询/导出不受限。
- **慢查询优化**：Explain 计划条形/错估；DBDelve 的 `×76 misestimate` 是最直观的信号。
- **运营 CSV 灌库**：映射 + 逐列类型 + SQL 预览 + 失败行说明；避免「导到一半发现日期全错」。
- **陌生库摸底**：对象过滤 + 表体积 + 结构页 + FK 导航；ER 图是 DBDelve 的加分项，但 DB Studio 不做。
- **多环境切换**：`⌃\`` 切连接、palette Connections、颜色/模式提示；减少「在 prod 上改错」。

## 9. 与 DB Studio 的对照：差距在哪、哪里已经领先

| 维度 | DBDelve | DB Studio 现状 | 结论 |
|---|---|---|---|
| 运行时/启动 | Rust/GPUI，1.13s / 133MB | Electron 44，预算 ≤1.5s / ≤250MB | 路线不同，DB Studio 已在预算内；不追原生 |
| 多引擎 | 11 + ODBC | MySQL 优先 | 范围差异；未来 PG 时借 `EngineSpec` |
| 网格 | 文本化 + 双轴虚拟化 | 列式 ArrayBuffer + 只解可视区 + 编辑深度更强 | DB Studio 在编辑/内存上更优；不要退回文本化 |
| 写安全 | 三档模式 + AST 白名单 + 事务内校验 | 脏单元格 + 逐条预览 + 冲突检测 + 无主键只读 | 各有优势；DB Studio 更严格，别照搬 Full/Row 模式 |
| 表设计器 | 无（结构只读） | 字段/索引/FK/DDL 预演 | **DB Studio 领先**，保持 |
| 执行计划 | 条形/self/actual/est/错估 | 树/表格/access/cost/detail，无 actual/self/错估 | **明显差距** → DB-02 |
| 行检查器 | 当前行全字段/JSON/编辑 | 详情面板是表信息/字段/DDL；单元格值走弹窗 | **明显差距** → DB-01 |
| 结构页 | 独立 Structure tab | 设计器模态 + 详情 DDL | **差距** → DB-04 |
| 导入 | 逐列 Parse as + NULL/空串 + SQL 预览 | 映射 + 预览校验；无 SQL 预览/空字段语义 | **差距** → DB-03 |
| 命令面板 | 6 scope + 分组 + 键帽 | 表/命令/历史 3 模式 | 小差距 → DB-05 |
| 状态栏透明 | 行数/字节/耗时/截断集中 | 行数/ms/截断分散 | 小差距 → DB-06 |
| 补全 | 别名 + FK JOIN ON | 别名 + 列补全；未见 JOIN ON 推断 | 中差距 → DB-07 |
| 首启 | URL/引擎/项目/导入 | 只有「新建连接」空态 | 小差距 → DB-08 |
| 文件拖入 | SQL 开标签 / CSV 开 DuckDB | 无窗口 drop | 小差距 → DB-09 |
| 主题 | 29 套 + 导入 | 单主题浅/深 | **刻意不追** |
| 无障碍/i18n | 弱 | 中文 + aria 规范 | **DB Studio 领先** |
| 许可 | GPL-3.0 | MIT | 只学设计，不复制代码 |

**DB Studio 已经做得更好、不必自卑的部分**：表设计器、网格编辑深度（批量/表达式/转置/
冻结列/FK 导航）、写入预演与冲突检测、中文界面、macOS 原生玻璃、文档与门禁。
本轮迭代应聚焦「信息面」，而不是重做底座。

  - 不改任何快捷键；保留现有 density 逻辑；
  - 先做 A/B 截图对比，确认不降低高频操作效率。
- **成本/风险**：小（1 天）；风险是用户习惯、发现性下降。
- **验收**：宽度断点不溢出（`verify:toolbar-fit`）；核心动作仍一键可达；偏好设置可改行高/主题。

---

### P3-12 列虚拟化（先测量，不默认做）

- **参考依据**：DBDelve 双轴虚拟化；DB Studio `DataGrid.tsx` 目前渲染全部可见列
  （`columns.map`，无水平窗口化）。
- **预期收益**：200+ 列宽表横向滚动更稳；减少 DOM 数量。
- **适用条件**：先用 200/500 列真实表测帧时间；若滚动 >16ms/帧或 DOM >5k 再做；
  必须保持冻结列/选区/编辑/列宽拖拽语义。
- **成本/风险**：大（1-2 周）；风险高（选择/编辑/冻结列交叉）。
- **结论**：**暂不做**；列入性能观察，不占用本轮预算。

### P3-13 会话结果快照恢复（谨慎）

- **参考依据**：DBDelve `GRID_ROW_CAP=5_000` + `snapshot from 3m ago`；DB Studio 明确只恢复
  tab 元数据、不存 payload（`sessionSnapshot.ts` 注释）。
- **预期收益**：重启即见上次结果，减少「重新查一遍」。
- **适用条件**：只存前 200-500 行；显式标「快照/可能过期」；切回 tab 自动刷新；
  不用于写前判断；有容量清理。
- **成本/风险**：中；风险是陈旧数据误导、磁盘/内存、与「恢复即重拉」的既定设计冲突。
- **结论**：**暂不做**；除非用户明确要求「上次结果立刻可见」，否则保持现有轻量恢复。

### P3-14 可重绑定快捷键（观察）

- **参考依据**：DBDelve 115 条注册 + override + 冲突单测；DB Studio 已有动作目录 + 只读速查。
- **预期收益**：个人习惯自定义。
- **适用条件**：需要同步原生菜单 accelerator、CodeMirror、网格/树局部 keydown；
  还要处理冲突/重置/导入导出。
- **成本/风险**：大；单用户收益低，且容易引入「菜单与页面两套键位」的旧病。
- **结论**：**暂不做**；先把「键帽提示 + 速查表」做扎实。

### P3-15 App.tsx 分层（工程项，随 P0/P1 局部做）

- **参考依据**：DBDelve `workspace/*` 按领域拆（tabs/queries/editing/profiles/import/exports）；
  DB Studio `App.tsx` 6,324 行，已有 `workspace/` 子模块但仍偏大。
- **预期收益**：降低「改一处、坏另一处」的回归风险；为行检查器/结构页提供清晰落点。
- **适用条件**：只做「无行为变更」的抽取（纯函数/控制器/hook）；每步跑 `npm test` +
  `e2e:ui`；不做大爆炸重构。
- **成本/风险**：大；风险是重构本身引入回归。
- **结论**：**不单独立项**；在 DB-01/DB-04 实现时顺手抽取相关状态，保持小步。

## 12. 落地顺序与门禁

### 12.1 三批落地

**Batch 1（P0，约 8-12 天）**
1. DB-01 行检查器：先只读，再编辑；复用现有脏单元格/预览链路。
2. DB-02 计划 2.0（估算版）：先 fixture/单测，再接 UI；`ANALYZE` 另开。
3. DB-03 导入 SQL/空值/逐列：先做 SQL 预览与空值语义，再做逐列 Parse as。

**Batch 2（P1，约 7-10 天）**
4. DB-04 Structure tab（只读）。
5. DB-05 Connections scope。
6. DB-06 状态栏透明度。
7. DB-07 FK JOIN ON 补全。

**Batch 3（P2，按容量）**
8. DB-08 欢迎页；DB-09 拖拽；DB-10 表体积/陈旧；DB-11 工具栏减负。

### 12.2 每批必须过的门禁

```bash
npm run typecheck
npm test
npm run check:bundle
npm run e2e:ui
npm run e2e:keys        # 改键位/面板/全局快捷键时必跑
npm run verify:toolbar-fit  # 改工具栏/状态栏时必跑
node docs/design-mockups/verify.mjs  # 改样式时浅/深双主题截图
```

- **行检查器**：断言「编辑后面板/网格脏计数一致」「切换 tab 不串行」；
  **不得**新增写路径；`decodeAll/materialize` 零调用。
- **计划**：固定 JSON fixture 单测；解析失败降级；不得把 plan 依赖打进首屏
  （`check:bundle` 特征串）。
- **导入**：SQL 预览与执行同源；空字段选择改变 SQL；非法行阻塞；
  `e2e:transfer` 必须真跑。
- **结构页**：只读；编辑跳设计器；不新增 DDL 构造。
- **面板/快捷键**：`e2e:keys` 覆盖 `⌘K`/`⌘P`/`⌘W`/`Esc`/方向键；焦点归还。
- **门禁可证伪**：新断言先在错误实现上确认会红，再改回；不要写「demo 后端恒真」的断言。

### 12.3 度量

- 宽表（100+ 列）行检查器：打开到可读 ≤200ms；滚动不新增长任务；
- 计划：首屏渲染 ≤100ms（100 节点内）；无新依赖；
- 导入：预览 1,000 行 SQL ≤300ms；导入失败率/重试次数下降；
- 面板：`⌘K` 到结果 ≤100ms；`Connections` 搜索 ≤50ms；
- 状态栏：结果完整性误判（以为全量其实是截断）归零；
- 全局：`npm run verify` 全绿；首屏 bundle 仍 ≤1.5MB；编辑器 chunk 仍 ≤150KB gzip。

## 14. 最终判断

DBDelve 的价值不在「它有哪些功能」，而在它把三个常被口号化的目标做成了工程事实：

1. **快**：原生渲染 + 流式 + 双轴虚拟化，而不是「把 Electron 调优到能接受」；
2. **可信**：不改写用户 SQL，生成 SQL 走白名单并从 AST 回读，写前审阅、事务内校验；
3. **可读**：计划条形、行检查器、结构页、状态栏，让数据/计划/结果自己解释自己。

DB Studio 不需要变成 DBDelve：它的 Electron/macOS 原生观感、MySQL 深度、表设计器、
写安全与中文体验已经是自己的护城河。**本轮最值得做的，是把 DBDelve 的「信息面」
（行检查器、计划可视化、导入 SQL/NULL）补到与自身写安全同等的高度**；
其次是「键盘路径」（Connections scope、状态栏透明度、FK 补全），
最后才是「上手的愉悦」（欢迎页、拖拽、表体积）。

> 迭代清单的取舍标准只有一条：**是否让「连接 → 定位表 → 查/改数据」这条闭环更快、
> 更可信、更少歧义**。不满足这条的，即使 DBDelve 做得再漂亮，也不进 DB Studio 的路线图。
