DB Studio 整套界面方案：深色科技精密风

以参考选型报告中「深色科技精密风」为基调，为 DB Studio 输出一套可直接评估的完整 GUI 方案。 页面既是可点可切的预览（明暗双模、强调色、树展开、标签切换、命令面板、写预演弹层都能实际操作）， 也是规范文档（token 表、栅格、控件态、键盘映射、操作闭环）。

先说三处必须调整的地方。参考风的原始取值有三项与本项目既有红线冲突，方案里已做替换而不是照抄： ① 强调色 #5E6AD2 是紫蓝，撞项目「禁紫/紫蓝渐变」设计红线 → 换成冰青族； ② 原始建议引入 Inter / Geist / Berkeley Mono 外部字体，撞项目「字体锁定系统栈」约束 → 保留 SF / 苹方，仅数据列用 SF Mono； ③ 原始风格主张「不用 backdrop-filter」，而项目方案 A 靠 CSS 毛玻璃做侧栏质感 → 给出二选一建议。其余（行高 28px、4px 栅格、发丝描边、近黑画布）与现有工程天然吻合。

01

设计基调与取舍

这不是「换一套配色」，而是把产品的隐喻从「原生精致」换成「精密仪器」。隐喻一换，材质、层级、密度、状态的表达方式全都跟着换。 但工程骨架不动 —— 三栏布局、虚拟滚动、列式传输、只读双层防线一条都不改，本方案只落在视觉与交互层。

产品隐喻

换的是说法
现在「macOS 原生精修应用」—— 柔和、克制、像系统自带的工具
改为「精密仪器面板」—— 读数清晰、刻度严密、状态可信、长时间盯不累
收益暗底让状态色与数据可视化自发凸显，等于免费多一维视觉编码
代价浅色模式容易失色沦为普通后台，必须单独设计而非简单反转

与现状的三处冲突

必须处理
强调色 冲突 紫蓝 #5E6AD2 撞设计红线 → 换冰青 #3BA9C9，语义色空间完全释放
字体 冲突 外部字体被项目锁定 → 保留系统栈，数据列用 SF Mono + tabular-nums
材质 取舍 玻璃侧栏 vs 纯色台阶 → 倾向降不透明度保留玻璃，见 §02
为什么强调色必须换：高密度界面依赖颜色做第二维度编码（NULL / 脏 / 错误 / 只读 / 选中）。 品牌色一旦落在紫蓝，语义色（绿黄红）与它的区隔就被压缩 —— 这正是参考报告里「状态色必须与品牌色分离」那条硬约束。 DB Studio 的语义色负载比一般工具更重（NULL、脏单元格、错误、只读、生产标签至少五类），这条约束必须执行到位。
02

色彩与材质

暗色板不是「黑底 + 白字」，而是带蓝调的近黑台阶：明度分三层表达层级（画布 → 卡片 → 浮层）， 几乎不靠阴影。这样做的直接好处是滚动热路径上没有任何模糊运算，与本项目 ≥55FPS 的性能门槛方向一致。

候选深色 / 浅色为什么是它风险
冰青（推荐） #3BA9C9 · #1F819A 仪表 / 示波器语汇，与「精密仪器」隐喻同源；与绿黄红语义色在色相上拉得足够开；暗底发亮不刺眼 浅色模式下略偏冷，需确认是否合口味
电光蓝（保守） #3E8FF0 · #2568D6 离现有 #0A84FF 最近，迁移成本最低，用户无感 与现有 Apple 蓝太近，「换风」的辨识度打了折扣
石蓝（极克制） #93A6BA · #5B6E82 单色强调，把语义色空间 100% 让给状态；最接近参考报告「近无彩灰阶」的极端形态 强调力度弱，主按钮与选中态不够跳，需要靠字重补偿

材质与层级规则

维度规则与现状的差异
层级表达 靠背景明度台阶（#08090A → #0F1011 → #1A1C1F），阴影只用于真正浮起的层 收益 减少合成开销，滚动更稳
描边 结构分割 1px --border；行内分割 1px --rowline（更暗一档）；不用粗边框 微调 现工程 border 只有一档，新增行内档
圆角 4 / 6 / 10px 三级（按钮 6、输入框 6、卡片 10、标签 4） 收紧 现为 6 / 8 / 12，整体收 2px 更「硬朗」
阴影 常态零阴影；浮层 0 16px 44px rgba(0,0,0,.62)，深色下靠亮度差 + 描边替代 收益 比现状更省，浮层仍清晰
侧栏材质 建议：保留玻璃但提高不透明度（现为 sidebar 毛玻璃 + 内容不透明，方案 A 已定） 待定 纯色台阶更贴参考风，但会丢掉 macOS 27 观感，见下方建议
字体 UI 用 -apple-system / SF Pro Text / PingFang SC；数据与 ID 用 SF Mono + tabular-nums；字号 13px 基准，负字距 -0.011em 不变 符合项目字体锁定约束，不引入外部字体
关于侧栏玻璃的取舍建议：参考风的立场是「内容区绝对干净、不用 backdrop-filter」。 但 DB Studio 的侧栏不属于内容区 —— 它是不透明的树，不存在「模糊底纹与密集文字抢注意力」那个问题。 因此建议保留现有 CSS 毛玻璃侧栏，只把背景不透明度从当前值抬高到 ~0.72：既留住 macOS 27 的观感， 又让侧栏底色更贴近深色的近黑台阶，与新皮肤自然衔接。内容区（网格 / 编辑器）保持完全不透明，这一条不动。

浅色模式的设计要点

易失手
不做反转浅色不是深色的取反。近黑画布在浅色下必须换成纯白画布 + 冷灰面板，否则发灰发脏

语义色降饱和绿黄红在浅底上原值会刺眼，统一压一档

操作流程

北极星指标是「单日完成 连接 → 定位表 → 查改数据 闭环的次数」，所以主流程上的每一步都被压缩到最少动作。 下面这条链是产品的心脏，任何新功能都不应插进这条链中间。

STEP 1
建立连接

侧栏「+」新建；已存连接的密码走 safeStorage 解密，不弹窗。「连接」按钮点一次直连。

表的定位策略为 none While 表无主键且无唯一键，网格应为只读，隐藏勾选框与脏标记 State-driven
连接处于只读模式 If 只读连接收到写语句，系统应拒绝执行并记录被拦截的语句 Unwanted
查询长时间未返回 When 用户点取消，系统应发送 KILL QUERY 并使查询真正提前返回 Event-driven
SSH 转发被服务端禁用 If forwardOut 既不 accept 也不 reject，系统应在独立超时后关闭隧道并报错 Unwanted
流程产物建议流转：本条主流程对应 PRD-v1.0 §6 的界面描述。 方案定稿后可把「第 5–6 步的写操作可预演」拆成事项分配给研发，并邀请测试同学关注 「逐格提交 / 无唯一键只读 / 只读连接拦截」这三条红线的回归范围。
08

危险操作与二次确认

DROP / TRUNCATE / 无 WHERE 的改删一律二次确认；生产连接再叠一层红色。这是产品安全观感的来源， 也是新皮肤里唯一允许使用高饱和红的地方 —— 语义色在这一刻必须压倒所有审美考虑。

危险分级

L1 普通写有主键定位的 UPDATE/DELETE 单行 → 写预演弹层，一次确认
L2 影响面无 WHERE / DROP / TRUNCATE → 二次确认 + 输入表名
L3 生产连接被标记为生产 → 弹层顶部红色标签，配色强制切到危险色，不跟随皮肤
拦截只读连接的任何写语句 → 主进程 AST 白名单拒绝，渲染层拦截不算防线

皮肤与安全的边界

可以换普通按钮、选中态、强调色、背景台阶、圆角
不能换危险色 #EB5757、只读锁定的置灰、生产标签红
原因这些颜色是安全语义，一旦跟着皮肤漂移，用户的危险直觉就会失效
实现它们定义为独立 token（--danger-fixed），不参与主题变量替换
