## 二、必须记住的几个取舍

### 1. DDL 的唯一构造处：`database/ddlTemplates.ts`

所有新入口拼 SQL 都走这一个零 React 依赖的模块（`buildCreateDatabaseSql` / `buildDropDatabaseSql` /
`buildRenameTableSql` / `buildCopyTableSql` / `buildMaintenanceSql` / `buildObjectTemplate` / `toCreateOrReplaceView`）。

三条硬约束写在模块头注里，配 26 项单测：

- 标识符一律 `quoteIdentifier/quoteQualified`（红线 5），**绝不手拼反引号**；
- 名字先过 `validateNewName`（空/超长/控制字符/`.` `:` `/` 禁用/重名大小写不敏感）；
  🔴 `.` `:` `/` 在本产品里**有结构含义**（限定名分隔符 / 树 key 分段 / 分组路径），必须禁；
- charset / collation 是**裸值**，过 `[A-Za-z0-9_]+` 白名单才允许拼进 SQL。

### 2. 🔴 守卫层的真实缺口：解析器不认这几种语句（0.7.3 实测）

`node-sql-parser 5.4.0` 实测：

- `DROP DATABASE \`x\`` / `DROP SCHEMA \`x\`` **解析失败**（去掉反引号反而能过）；
- `OPTIMIZE|ANALYZE|CHECK|REPAIR TABLE …` 完全不被识别。

后果：删库与表维护在 DDL 入口被永久判成「无法判定是否安全」——这不是安全，是功能缺失。

处理方式（`core-sql-guard/src/index.ts` 的 `ADMIN_DDL_FORMS`）是**只在解析失败之后**才走的文本兜底：

1. 能解析的语句 100% 仍走 AST 白名单，判据一点没松；
2. 形态是**闭合枚举 + 整串锚定**（`^…$`），任何分号/额外 token 都不匹配；
3. 归一化后仍含 `;` 直接放弃（多语句是注入最短路径）；
4. 原文含 MySQL **可执行注释**（`/`+`*`+`!` 开头）直接放弃 —— 归一化会把它当注释删掉，那等于藏语句。

净效果：**只把此前必然被拒的一类正常语句放进来**，不改变任何既有判定。
证据：`core-sql-guard/src/ddl-entry.test.ts`（25 项，含 10 项恶意/畸形输入的反例）。

### 3. 排序与「谁盖掉谁」：toast 与定位的先后顺序

`onRefreshConnSchema` 自己会 toast「已刷新表结构」，并且在内部 `setSchemas` 触发重渲染。
于是两个顺序都不能动：

- **定位意图必须在刷新之前登记**（`pendingRevealRef`）—— 树的 `useMemo` 依赖 `treeRoots`，
  刷新引发的那一次渲染就是 effect 唯一会跑的时刻；先 await 再登记 = 永远不展开；
- **成功回执必须在刷新之后** —— 否则被「已刷新表结构」盖掉，用户看到"刷新了"却不知道库建成了
  （e2e 第一次跑就抓到这条：断言拿到的是 `已刷新表结构`）。

### 4. 删除数据库为什么要比删表更严格

删表只在**生产红标**时要求输表名；删库**无条件**输入库名（审计红线）。同时修了一处口径错误：
`DangerConfirmModal` 把「要不要输名」和「是不是生产环境」混成一个布尔，导致非生产的删库弹窗
写着「这是生产环境连接」。现在判据只保留「需要输名」，环境文案归 `confirmDanger`（它才知道 `colorTag`）。

### 5. 复制表：两条语句必须分开走两条白名单

`CREATE TABLE … LIKE` 是 DDL，`INSERT … SELECT` 是写语句。混在一条里必被其中一套拒绝。
且两步不是同一事务：**结构成功、数据失败时如实说「表建好了但数据没进来」**，
不假装整体失败（否则用户会以为什么都没发生，再点一次撞重名）。

### 6. 分组是派生结构，所以「空分组」需要一份独立清单

分组由每条连接的 `group` 字段派生（`生产/订单` = 嵌套），没有独立存储。副作用是
**没有连接的分组不存在** —— 用户点「新建分组」后它会立刻消失。
于是新增 `dbstudio.emptyGroups.v1`（只存路径）+ `buildTree({ extraGroups })` 并进树里。
配套补了「删除空分组」（有连接的分组不给删并说明原因），否则新建就是单向门。

### 7. F2 让位

`tree-design-table` 的 F2 改绑 `Shift+F2`，新增 `tree-rename-table` = F2。
动作目录（`action-catalog.ts`）是键位唯一真源，改完重跑 `npm run gen:actions`。

### 8. 模板方案（P1-21 / P2-30）为什么不做设计器

五类对象的语法方言差异大（定义者、分隔符、触发器时机），半吊子设计器只会生成跑不通的 DDL。
模板给的是**单条语句、改了就能执行**的形态，并且**不含 `BEGIN … END`** ——
编辑器的 `splitStatements` 按 `;` 切分，块体会被切成几条废语句
（"填了模板 → 执行 → 语法错误"是最伤人的假实现）。

编辑器执行 DDL 后自动 `schemaRefresh`（关键字判定）：漏判的代价是树停在旧结构上，
用户会以为视图没建成；多刷一次的代价只是一次只读请求。

### 9. 🔴 行内入口的位置：连接行 hover 按钮是被 e2e 打回的方案

「新建数据库」最初做成连接行上的第 4 个 hover 动作按钮（与库节点的「+ 表」对称）。
真机 e2e 当场变红，而且两条都是**产品问题**不是测试问题：

- 连接行的动作区右对齐，4 个按钮约 100px，在 240px 侧栏里左缘已压到行宽中线 →
  **点连接行的中点弹出「新建数据库」对话框**，而不是选中这一行（原先 3 个按钮时中线是安全区）；
- 同一个弹窗的 `.modal-mask` 又让紧跟着的「拖左分隔条」拖不动（240 → 240）。

现在入口挂在**库列表尾部**（`addDbAfter`：已展开连接的最后一行「＋ 新建数据库」，缩进按连接层级 +1），
且刻意**不用 `.tree-row` 类** —— 它不是树节点，不参与选中/键盘巡行/多选/`.tree-row` 计数。
代价是少一处"手就在连接上"的发现性，换来的是点行不会误触；右键菜单与命令面板两条路径仍在。

### 10. 表设计器：全仓唯一退不出的模态（顺带修掉）

`App` 的全局快捷键闸门只拦「非 Esc」，注释里写着「Esc 仍留给模态关闭，见各弹窗的 onKey」——
但 `TableDesigner` 从来没有任何 keydown，于是它是全仓唯一"只能点遮罩/点取消"才能退出的模态。
e2e 里按 Esc 关不掉，残留 `.modal-mask` 把后面所有点击吃掉（表现为一串 30s 超时）。
现在补了 window-capture 的 Esc 关闭（`saving` 期间不关、内层还有弹窗时让给内层），
底部「取消」也补了 `data-testid="designer-cancel"`。

### e2e 判据上的三处修正（都是"断言看起来在测，其实测不到"）

1. **不能按标签定位树行**：`filter({ hasText })` 是子串匹配，`access_log` 命中 `access_log_zz`；
   更要命的是 demo 里两个连接共享同一份库结构，同名表会出现两行 —— 改名后"旧表名消失"永远为假。
   现在树行带 `data-node-key`（`obj:<connId>:<db>:<table>`，全局唯一），断言精确到「哪个连接下的哪张表」。
2. **不能按子串点菜单项**：`hasText: '复制表'` 会先点掉「复制表名」（DOM 里还排在前面），
   于是复制表弹窗永不出现，看着像"点了没反应"。`clickMenu` 改成精确等值（末尾 `…` 可选），
   找不到就把实际菜单项全列出来报错。
3. **设计器没有关闭用例**：见上文第 10 条 —— 关闭失败会让后续每章 30s 超时连坐，
   所以「退出后无残留遮罩」单独一条断言，兜底点击只做 best-effort 清理、判据仍在断言里。
