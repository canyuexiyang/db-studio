### P2-18j 详细设计（本迭代最重的安全口径）

- **导出**：`buildConnectionBundle` 用**白名单**取字段（不是 delete 密码）——
  以后给 ConnectionConfig 加任何新字段，白名单自动挡在导出之外；
  SSH/SSL 是**嵌套对象**，各自再过一遍白名单（`ssh.passwordEnc` / `ssh.passphraseEnc` /
  `ssl.keyPath` 等一律不带）。私钥**路径**虽非秘密也不带：换机后指向不存在的文件，
  只会"看起来配好了"。导出后强制 `promptEveryTime: true`（没有密文可带）。
- **导入**：整体拒绝（一条不合法就不导，批量操作"少几条"最难发现）；重名**自动改名**
  （`name (2)`，大小写不敏感）而不是覆盖本地 —— 覆盖会连带丢掉本地那条的密码。
  即使文件被手工塞了 `passwordEnc`，也强制 `passwordEnc: null` + 每次手输。
- **IPC**：新增 `connbundle:pick` / `connbundle:save` 两条通道（不复用 `sqlfile:pick`
  —— 让用户在"打开 SQL 文件"的框里找 .json 是误导）；主进程只搬字节不认识格式，
  且**不接受渲染层传路径**（写盘一律弹保存框），防渲染层被注入后借道读写任意文件。
- 🔴 真机 e2e 抓出一个接线错误：主进程 `ConnectionStore.save()` 只认**顶层**
  `input.promptEveryTime`，config 里那个字段会被 normalize 掉 → 只传 config 的导入
  **必然全条失败**（校验器拒绝）。已在调用点修复并留注释。
- demo 侧**明确说做不到**（抛「需要桌面应用环境」），不是静默取消。

## 顺带修复（非审计项，但都是门禁抓出来的真问题）

1. **e2e:app 的 V23 收尾关错了窗口**：`getAllWindows()[length-1]` 在这台机器上是
   主窗口 —— 关掉后 9.6 之后的所有 `page.*` 都在已关闭页面上操作，
   「无控制台错误」成了永远为真的假绿。改为按**窗口 id 差集**关新窗口 + `destroy()`。
2. **`backend.ts` 注释里混入两个 NUL 字节**（0.6.0 的分隔符注释），导致 grep 视其为
   二进制文件、文本检索静默失效。已替换成转义写法。
3. **功能弹窗 chunk 预算 60 → 64KB**：P1-12/P1-10/P2-18d 给弹窗补的真功能（手写代码，
   无新依赖），涨预算留痕。
