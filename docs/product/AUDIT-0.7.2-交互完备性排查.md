# DB Studio 0.7.2 交互完备性排查（右键与操作入口全量对照）

> 排查时间：2026-10-29（v0.7.2 发版次日）。
> 起因：真机反馈「连接右键没有新建库选项，只有已有库下能右键新建表」。
> 方法：宿主分级菜单（App.tsx）+ 树侧菜单（TreeView.tsx）逐项枚举现状 → 与 Navicat / TablePlus / Sequel Ace 的同类入口逐项对照 → 缺失项全部用 ripgrep 在全渲染层复验（排除工具假阴性）。
> 附带核实：0.7.2 的 27 个子任务**确认全量落地**（此前抽查的 P1-7/9/10、P2-18a「疑似未做」均为检索工具假阴性，已逐一用 ripgrep 推翻）。

## 二、缺失清单（按优先级）

> 优先级口径：**P0** = 对象生命周期闭环断裂（能浏览不能创建/删除）；**P1** = 高频动作缺失或名实不符；**P2** = 低频/打磨。

### P0-19 新建数据库（用户真机反馈，全代码库零实现）
- **问题**：连接已建立、库列表可见，但**任何地方都建不了库**——连接级右键无「新建数据库」，库区无 `+` 行内按钮，命令面板无对应命令，设计器只管表。全渲染层 ripgrep 复验：唯一命中是一句注释（`App.tsx:3202`「用户可能在脚本里 CREATE DATABASE」——产品自己都知道这个场景，却只能让用户手写 SQL）。
- **建议**：①连接级右键 + 库区末尾行内 `+ 库` 按钮，弹小型对话框（库名 + 字符集/排序规则默认 utf8mb4，只读提示即可），执行 `CREATE DATABASE`（走 DDL 白名单通道 + 危险确认第二层）；②命令面板加 `:createDatabase`；③完成后 schemaRefresh + 展开定位新库。只读连接禁用并给原因。
- **影响范围**：所有新环境初始化场景。竞品 Navicat/TablePlus/Sequel Ace 全部标配。
- **证据**：ripgrep `新建数据库|CREATE DATABASE|createDatabase` 全渲染层仅 1 注释命中；连接级菜单 `App.tsx:3355-3408` 无此项。

### P0-20 删除数据库（有守卫无入口）
- **问题**：`core-sql-guard` 对 `DROP DATABASE` 有完整的第三层保护（requireName=库名），但树上**没有入口**——库级右键没有「删除数据库」。结果是最危险的 DDL 只能去 SQL 编辑器手写，而树的危险保护体系（入口禁用→确认→输库名）在这条路径上完全缺席。
- **建议**：库级右键加「删除数据库…」，复用 `onTableDestructive` 的危险三层（生产红标 / 输库名）；执行后关该库所有标签 + schemaRefresh。**必须**走 danger 第三层——这条比删表更该输名。
- **影响范围**：环境清理/重建场景；安全红线的覆盖完整性（守卫能力已建、入口缺位=白建）。
- **证据**：库级菜单 `App.tsx:3409-3432` 无此项；守卫已支持 `core-sql-guard/src/index.ts:357-364`。

### P1-21 新建视图 / 存储过程 / 函数 / 触发器 / 事件
- **问题**：树能浏览全部 6 类对象，但只有「表」类别有新建入口。视图等 5 个类别右键只剩「刷新」——**能看不能建**。
- **建议**：最小集先做**视图**（高频）：类别/库级右键「新建视图」→ 新查询标签预填 `CREATE VIEW … AS SELECT` 模板 + 执行后刷新。过程/函数/触发器/事件同模板方案（不建专用设计器，符合克制路线）；执行成功后 schemaRefresh。
- **影响范围**：视图是查改数据工作流的一部分（筛选固化、报表口径），频率高于过程/函数。
- **证据**：类别级菜单 `App.tsx:3433-3449` 仅 `objectKind === 'table'` 有新建项。

### P1-22 重命名表 + F2 语义修正（名实不符）
- **问题**：`RENAME TABLE` 全代码库无入口；树上按 F2 **打开的是表设计器**（`App.tsx:4293` 把 onRenameRequest 接到 setDesigner）——F2 在 Finder/VSCode/Excel 的肌肉记忆都是「重命名」，这里是「进设计器」，名实不符。且设计器编辑模式下表名锁定（0.7.1 审计已知）。
- **建议**：①表对象右键 + F2 改为弹「重命名表」对话框（`RENAME TABLE`，走 DDL 通道 + 确认），成功后关旧标签/定位新表 + schemaRefresh；②「进设计器」的键位换成 ⇧F2 或右键菜单即可（它已有 4 个入口，不缺这一个）。
- **影响范围**：表名拼错/口径调整的高频小场景。
- **证据**：ripgrep `RENAME TABLE|renameTable` 零实现命中；`App.tsx:4293` F2→设计器接线；设计器锁名 0.7.1 审计 P1 项。

### P1-23 ObjectBrowser 右键菜单（升级浏览视图后仍缺）
- **问题**：0.7.2 已把中间面板升级为可切换的「浏览对象」视图（决策选了升级路线），但清单项**仍无右键**——想导出/设计/复制限定名必须回左树。升级了定位，没升级操作完备度。
- **建议**：清单项右键复用宿主分级菜单构造（`openNodeMenu` 同一入口，传对应节点），对象级动作全量继承；顺手补条目间 ↑↓ 键盘导航。
- **影响范围**：浏览态下的所有操作路径。
- **证据**：`ObjectBrowser.tsx` ripgrep `ContextMenu|onContextMenu` 零命中（此前 Bash grep 假阴性已排除）。

### P1-24 库级右键补「导出整库…」入口
- **问题**：导出弹窗支持「整库」范围（仅 sql/markdown），但**树上库级菜单没有导出项**——功能有、入口无，用户不知道这条路存在。
- **建议**：库级右键加「导出整库…」，直接打开 ExportModal 并预选 `database` 范围。
- **影响范围**：备份/搬迁场景的发现性。
- **证据**：库级菜单 `App.tsx:3409-3432` 无导出项；整库范围实现于 `exportScope.ts:131-142`。

### P1-25 连接右键补「测试连接」
- **问题**：改完 SSH/SSL 想验证必须打开编辑器→滚到底→点测试。连接级右键 10 项里没有这个高频动作（0.7.1 审计已提，未修）。
- **建议**：连接级右键加「测试连接」，直接 `backend.connTest`，结果 toast（带 serverVersion + 耗时，同编辑器口径）。
- **影响范围**：SSH/SSL 配置调试场景。
- **证据**：连接级菜单 `App.tsx:3355-3408`；connTest 已有 `ConnectionEditor.tsx:250-271`。

### P1-26 标签右键补「关闭左侧」「关闭全部」
- **问题**：0.7.2 已加固定/关闭其他/关闭右侧，但缺「关闭左侧」「关闭全部」——重构/清理工作区时的标准动作（浏览器/VSCode 标配）。
- **建议**：复用 `planBatchClose` 批量脏守卫（一个确认框列全部脏标签，支持逐行保留），排除固定标签。
- **影响范围**：多标签工作流收尾。
- **证据**：`tabContextMenuModel.ts:266-314` 仅 6 项；批量守卫 `tabContextMenuModel.ts:129-143` 已有。

### P2-27 表维护：优化表 / 分析表 / 检查表
- **问题**：Navicat 表右键标配的 OPTIMIZE / ANALYZE / CHECK（+ REPAIR）全无。碎片整理、统计信息更新是慢查询排查的常规手段。
- **建议**：表右键加「表维护」二级菜单（三项即可），走 DDL 通道 + 轻确认（这些是安全操作，不必第二层），结果 toast 报告各语句的服务端回执。
- **影响范围**：DBA 侧维护场景（频率中等，与「面向开发者」定位匹配度一般，故 P2）。
- **证据**：ripgrep `OPTIMIZE TABLE|ANALYZE TABLE|CHECK TABLE` 零命中。

### P2-28 复制表（结构 / 结构+数据）
- **问题**：`CREATE TABLE … LIKE` + `INSERT … SELECT` 组合无入口。做实验副本、迁移前快照都要手写两条 SQL。
- **建议**：表右键「复制表…」对话框（新表名 + 是否带数据 + 目标库默认同库），预览生成的两条 SQL（沿用强制预览红线），走 DDL+DML 通道。
- **影响范围**：实验/备份场景。
- **证据**：ripgrep 无实现。

### P2-29 分组管理：新建 / 重命名分组
- **问题**：连接分组目前只能进每个连接的编辑器里手输 `生产/订单` 路径字符串；分组节点右键只有「新建连接」。想整理分组结构 = 逐个编辑连接。
- **建议**：分组右键加「重命名分组」（批量改该组连接的 group 前缀）与「新建分组」（创建空分组或并入）；实现是纯 ConnectionStore 字段批量更新。
- **影响范围**：连接多于 10 个的组织场景。
- **证据**：分组级菜单 `App.tsx:3514-3516` 仅 1 项。

### P2-30 视图设计器（观察项）
- **问题**：视图不可结构编辑（工具栏明示）。改视图 = 手写 `CREATE OR REPLACE VIEW`。
- **建议**：本版本**不做**——做正经视图设计器（列来源映射、JOIN 可视化）投入大且偏离「快」主线。缓解方案：视图右键加「在新查询中打开定义」（预填 `CREATE OR REPLACE VIEW … AS <当前定义>`），让「改视图」至少一步到位。归入 P2-21 的模板方案顺带做。
- **证据**：`App.tsx:4458`「视图不可结构编辑」。

## 三、执行建议

**0.7.3 建议范围**：P0-19/20（库生命周期闭环）+ P1-21~26 六项（入口补齐，均为小~中成本）+ P2-30 的模板缓解。P2-27/28/29 视余量。

**红线提醒**：
- 新建/删除库、新建视图模板都走既有 `mutationApply` DDL 通道与 `roGuard` 只读守卫，不新增写路径；
- 所有 DDL 完成后统一 `schemaRefresh` + 标签同步关闭/定位（复用批量删表的 `deleted` 集合模式）；
- 每项补 e2e 断言前先在错误输入上确认会红。

**方法教训（记录给后续审计）**：本环境 Bash 的 grep 交替模式（`a\|b`）**不可用**——返回假空。多模式检索必须用 ripgrep（Grep 工具）。本轮初判「0.7.2 多项未落地」即为该假阴性所致，已全部推翻。
