## 三、改进清单（按优先级从高到低）

> 每条 = 问题 — 原因 — 建议 — 优先级 — 影响范围 — 证据。
> 优先级口径：**P0** = 用户会认为功能坏了 / 有 UI 但实际不可用 / 安全口径有破口；**P1** = 高频标配缺失，竞品均有；**P2** = 打磨项。

### P0-1 导出「选区/当前已加载」范围与「仅导出可见列」永久不可用
- **问题**：导出弹窗 4 个范围中 2 个永远置灰（提示「当前视图没有选区快照…」），「仅可见列」也永远置灰。0.7.0 发版说明宣称已落地的功能，实际不可用——属于「有 UI 但没接线」，且 UI 会在用户尝试时自曝其短。
- **原因**：`App.tsx` 挂载 `ExportModal` 时只传了 8 个 prop，未传 `selectedRows` / `loadedRows` / `visibleColumns`；即便传了，`resolveExport` 的 snapshot 分支也会直接报「快照导出暂未接入导出进程」。
- **建议**：二选一，**不要维持现状**。①接线：网格在打开导出时上报快照（选区行/已加载行/可见列），worker 增加 snapshot 通道（数据已在渲染层，无需重查，反而更快）；②收敛：从弹窗移除三个选项，只留「全部匹配/整库」，发版说明同步勘误。推荐①——「导出我看到的这些」是用户心智里最自然的范围。
- **影响范围**：所有导出用户；当前每次想用都会撞上禁用提示。
- **证据**：`App.tsx:4560-4580`（挂载未传参）、`ExportModal.tsx:94-98`（prop 声明）、`ExportModal.tsx:217-223`（snapshot 分支必然失败）、`exportScope.ts:102-118`（恒 disabled）。

### P0-2 树搜索搜不到未展开的库里的表，且连接名/库名完全不可搜
- **问题**：默认只展开到库层，未展开库的表按表名搜索**零结果**；连接名、库名、分组名在任何维度都搜不到。用户会判定搜索功能损坏。输入过程中无自动展开，只有按 Enter 才展开祖先链。
- **原因**：`flat = flattenTree(roots, expanded)` 只含已展开行，`filterFlatByQuery(flat, hits)` 把「全树扫描出的命中」过滤回「已展开的行」；`searchTree` 显式跳过非 object 节点。
- **建议**：搜索态下让 `filterFlatByQuery` 基于全树 flat（或对命中自动 `expandAncestors` 后再过滤）；`searchTree` 放开 connection/database/group 节点（命中容器节点显示为可点击行，点击=选中+展开）；顺手补结果计数（「命中 N 条」）与输入框清空按钮。
- **影响范围**：所有用树搜索的用户——表一多（几十张以上）搜索就是第一入口。
- **证据**：`TreeView.tsx:194`（flat 依赖 expanded）、`TreeView.tsx:204-207`、`core-tree-view/src/index.ts:411-422`（只搜 object）、`index.ts:450-465`。

### P0-3 激活标签不会滚进视野，`+` 新建按钮随滚动条消失
- **问题**：⌘9 跳第 9 个标签、⌘⇧] 循环、双击树新开第 N 个表——激活标签在视野外时视觉上「什么都没发生」；`+` 按钮在滚动容器内部，标签一多就被滚走。
- **原因**：workspace 目录无 `scrollIntoView` 调用；`.ws-tab-new` 是滚动容器的普通子项。
- **建议**：`WorkspaceTabsBar` 加 `useEffect(() => activeEl?.scrollIntoView({inline:'nearest'}), [activeId])`（约 5 行）；`+` 按钮移出滚动容器改为右侧固定（与 VSCode/Chrome 一致）；中期补溢出下拉列表。
- **影响范围**：标签 ≥8 个的所有场景。成本极低、收益即现，**全清单 ROI 最高**。
- **证据**：`WorkspaceTabsBar.tsx:143-196`（无 scrollIntoView、`+` 在容器内）、`styles.css:3015-3016`。

### P0-4 生产环境判定用错连接对象（结构性风险，当前侥幸未爆）
- **问题**：`confirmDanger` 用 `activeTab?.connId ?? connections[0]?.id` 判定是否红标生产库，**不是操作目标所在连接**。目前 6 个调用点都显式传了 `requireText` 才没出事；任何一个新调用点漏传，就会出现「对生产连接操作不要求输表名」或反向误拦。
- **原因**：判定语义依赖「当前激活标签」这个无关状态。
- **建议**：`confirmDanger` 签名改为必须显式传目标 `connId`（编译期强制）；单测覆盖「A 连接非红标、B 连接红标」交叉场景。
- **影响范围**：所有危险操作的未来调用点；数据安全红线。
- **证据**：`App.tsx:802-806`（判定取 activeTab）、`App.tsx:2758-2907` 等 6 处调用点。

### P0-5 生产库上网格删行/批量更新缺第三层保护
- **问题**：连生产库（红标）删行、批量编辑，只过 `SavePreviewModal` 普通预览，不要求输表名——与删表/DDL 的保护强度不一致。而删行恰恰是生产库上最高频也最不可逆的操作。
- **原因**：删行走 `grid/SavePreviewModal` 通道，不经 `danger/DangerConfirmModal` 第三层；两轨制未对齐。
- **建议**：`SavePreviewModal` 接受 `requireText`：当目标连接 `isProduction` 且含 DELETE/无 WHERE UPDATE 时，升级为输表名确认（复用 DangerConfirmModal 的输入组件，文案区分）。
- **影响范围**：生产库写操作场景。
- **证据**：`App.tsx:2179-2208`（预览通道）、`DangerConfirmModal.tsx:90-109`（第三层实现，删行未接入）。

### P0-6 BLOB/Date 单元格正文渲染与复制口径分裂
- **问题**：BLOB 格子正文显示为 `137,80,78,71,…`（逗号分隔字节串），Date 对象显示浏览器本地格式；而右键复制输出 `(二进制 N B)` / ISO 格式。同一格「看到的」与「复制到的」不一致，且字节串毫无可读性——与数据保真红线的展示侧相违。
- **原因**：网格正文渲染用裸 `String(v)`，未走与复制路径同一的 `cellToDisplay()`。
- **建议**：正文渲染统一走 `cellToDisplay`（BLOB 显示 `(二进制 N B)`，可点击打开 CellValueModal 看图/HEX）；Date 显示 ISO 裁剪口径。注意滚热路径纪律：`cellToDisplay` 需在解码层预算内（已是列式解码，逐格调用可接受，需跑一次 `e2e:grid` 性能门禁验证）。
- **影响范围**：任何含 BLOB/DATE 列的表。
- **证据**：`DataGrid.tsx:2452`（`String(v)`）、`core-clipboard/src/index.ts:29-35`（`cellToDisplay` 口径）。

### P1-7 标签管理三件套缺失：拖拽排序 / 固定 / 双击关闭
- **问题**：竞品与浏览器均标配；`tabContextMenuModel.ts:39-45` 注释自述「v0.7.0 还没有固定标签（T42 才做）」，即已排期未做。连带：关闭其他/右侧在有固定标签后需排除固定项。
- **建议**：先做拖拽排序（`useWorkspaceTabs` 加 `moveTab(from,to)`，pointer capture 复用 PanelResizer 模式）与固定（`pinned` 字段 + 关闭守卫排除），双击关闭可选。
- **影响范围**：多标签重度用户。
- **证据**：`useWorkspaceTabs.ts:66-84`（无 reorder）、`WorkspaceTabsBar.tsx:143-193`（无 draggable）。

### P1-8 克隆连接缺失
- **问题**：「基于生产连接建一个测试连接」需手抄全部字段（host/SSH/SSL 十几项）；现有「复制连接信息」只产出脱敏文本。
- **建议**：连接右键加「创建副本」，进入连接编辑器并预填除密码外全部字段（密码经 safeStorage 不可明文读出，UI 显示「已保存」占位即可沿用）。
- **影响范围**：多环境用户（恰好是红标功能的目标人群）。
- **证据**：`App.tsx:3084-3088`（仅文本复制）、`TreeView.tsx:285-334`。

### P1-9 网格键盘入口缺口：打字即编辑 / F2 / Home/End/PgUp/PgDn
- **问题**：Excel/DataGrip/TablePlus 用户的肌肉记忆——敲字符直接进编辑——全部落空；无翻页键，长表只能拖滚动条。Esc 取消编辑即丢草稿（CellValueModal 里 Esc 保留草稿，两处不一致）。
- **建议**：可打印字符按键 → 以该字符为初值进入编辑（只读表给 toast 原因）；F2 = 编辑；Home/End = 行首/行尾列，PgUp/PgDn = 视口翻页；Esc 第一次取消保留「草稿暂存」、第二次清空（与 CellValueModal 对齐）。
- **影响范围**：所有键盘流用户。
- **证据**：`DataGrid.tsx:1315-1501`（无可打印字符分支/无翻页键）、`:1255-1262`（Esc 丢草稿）。

### P1-10 导入无编码 / 分隔符纠正 / 导入模式选项
- **问题**：GBK 或含 BOM 的旧系统导出 CSV 导入后静默乱码；分隔符探测错误无从纠正（state 存在但无输入控件）；仅 INSERT，无 replace/upsert。而 SQL 脚本入口反而有 utf8/gbk 选择——两个「导入」链路口径不一致，用户认知混乱。
- **建议**：最小集 = 编码下拉（UTF-8/GBK，peek 自动探测 BOM 预选）+ 分隔符输入（探测结果可改）；模式可先不做，但弹窗文案明示「仅追加」。`issuesToCsv` 已实现且有单测却从未被调用——失败明细「导出 CSV」按钮是纯接线活，顺手做掉。
- **影响范围**：从 Excel/旧系统搬数据的用户（中文环境 GBK 高发）。
- **证据**：`import-worker.cjs:89`（硬编码 utf8）、`ImportWizard.tsx:56,115,195`（delimiter 无控件）、`core-import/src/runtime.cjs:347`（issuesToCsv 无调用方）、`SqlScriptModal.tsx:234-241`（脚本入口有编码）。

### P1-11 Toast 无成功/失败分级、永不自动消失
- **问题**：成功消息（「已提交：影响 3 行」）和错误消息共用橙色警示底、常驻不消失；错误横幅会一直占位直到被下一条覆盖。用户无法一眼分辨「刚才那下成了还是炸了」。
- **建议**：toast 加 `tone: ok | warn | error` 三态（成功绿底/中性灰底，错误保持橙/红）；成功类 3-4s 自动消失，错误类常驻但可点 ✕ 关闭；保留点击复制错误详情（现有亮点）。
- **影响范围**：每一次操作反馈。
- **证据**：`App.tsx:574`（单一 toast state）、`App.tsx:4288-4299`（单一 .banner 样式）、全文件无 `setToast(null)` 定时器。

### P1-12 表设计器：ALTER 中途失败不回滚也不刷新 → 重复执行风险
- **问题**：多条 ALTER 逐条执行，第 k 条失败后前 k-1 条已落库（DDL 隐式提交无法回滚），但弹窗不刷新表结构，用户再点保存会**重新执行已成功的语句**；失败报告只有一行 toast。
- **建议**：失败后立即重新拉取 TableMeta 并重建 diff（已执行的语句自然消失）；失败报告结构化（「已执行 N 条 / 失败于第 N 条：原文 + 错误」）。中期可考虑编辑模式补齐「删除已有索引/外键」与改名（当前引导去 SQL 编辑器，体验断档）。
- **影响范围**：所有在线改表场景。
- **证据**：`TableDesigner.tsx:211-223`（逐条执行+catch 只 toast）、`core-table-designer/src/index.ts:625-626`（不读已有索引）。

### P1-13 树无虚拟化 + 键盘不可达
- **问题**：文件头注释声称「扁平化是上万节点唯一能撑住的形态」，但渲染是 `visible.map()` 全量 DOM——500 表的库展开即 500 行 DOM，每次按键搜索全量重算无防抖；树容器可 Tab 聚焦但 CSS 关掉了焦点环，且无 ↑↓ 导航——「能进去但什么也做不了」。
- **建议**：虚拟化可后置（500 行 DOM 尚可承受，真到上万再上窗口化），但**键盘导航（↑↓/←→/Home/End/type-ahead）与焦点环应立即补**——这同时是无障碍与效率问题；搜索输入加 150ms 防抖。
- **影响范围**：大库用户、键盘用户。
- **证据**：`TreeView.tsx:491-686`（全量渲染）、`styles.css:4014-4018`（焦点环被关）、`TreeView.tsx:196-207`（无防抖）。

### P1-14 命令面板「最近使用」排序已建但数据未接线
- **问题**：`queryPalette` 支持 `lastUsedAt` 半衰期排序，但 App 传入的表条目从不带该字段——「最近打开过的表排前面」这个最符合直觉的排序实际不生效。
- **建议**：`openTableTab` 成功路径写 `lastUsedAt[connId:db:table] = Date.now()`（localStorage，随表视图记忆同 key 体系即可），palette 条目构造时带上。
- **影响范围**：⌘K 用户——当前最顺手的入口，值得让排序聪明起来。
- **证据**：`core-command-palette/src/index.ts:233-238`（排序支持）、`App.tsx:3393-3410`（不传 lastUsedAt）。

### P1-15 筛选器可发现性与打磨
- **问题**：无直接快捷键（⌘⇧F 未占用，建议占用之）；保存方案用 `window.prompt`（与 Apple 原生精修风格违和，代码自述技术债）；单条件无「临时停用」开关；无相对日期（datetime 只能手输字面量）；新条件默认列恒为第一列易被忽略。
- **建议**：⌘⇧F 打开筛选；prompt 换成与 SnippetSaveDialog 同款小对话框；条件行加启用开关（停用=不进 buildWhere，条件条灰显）；相对日期可后置。
- **影响范围**：筛选是「定位表之后找数据」的第一动作。
- **证据**：`App.tsx:3356-3386`（快捷键清单无 ⌘⇧F）、`FilterBuilder.tsx:391-392,426,439`（window.prompt 自述技术债）。

### P1-16 ObjectBrowser 定位尴尬：只在零标签时出现、无右键菜单
- **问题**：打开任何一个标签后中间清单整体消失；清单项无右键菜单（导出/设计/复制限定名都要回左树）；无搜索无排序无虚拟滚动。当前它更像「空态装饰」而非可用的对象浏览入口。
- **建议**：二选一明确定位。①做成**可切换的工作区视图**（与标签栏并存，工具栏加「浏览对象」切换），补右键菜单复用 TreeContextMenu；②若坚持克制路线，把它降级为纯空态引导，去掉「单击选中看详情」这类半成品交互，避免维护两套口径。
- **影响范围**：浏览库结构的用户路径。
- **证据**：`App.tsx:4259`（`ws.tabs.length === 0`）、`ObjectBrowser.tsx:56-73`（无右键 props）。

### P2-17 字号/间距无 token，深色主题三处维护
- **问题**：颜色 token 化彻底，但 `font-size` 散写 60+ 处（9/10/11/12px 各处字面量）、间距同理；深色调色板在 `:root[data-theme]` 与媒体查询块双份维护，改一处漏一处即主题不一致。
- **建议**：引入 `--fs-xs/sm/base` 与 `--sp-1/2/3` token 渐进收敛（不必一次改完，新代码先用）；深色双份维护已有注释警示，可加一条 lint/单测断言两块的 token 键集合相等。
- **影响范围**：长期维护成本；不影响用户。
- **证据**：`styles.css:9-41`（token 块）、`styles.css:216,253,324…`（散写字号）、`styles.css:43-47`（双份维护注释）。
