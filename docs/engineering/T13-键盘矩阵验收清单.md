# T13 · 键盘矩阵验收清单

> 对应任务：**T13「五焦点真机键盘矩阵验收」**（v0.7.0 / REQ-0.7.0）
> 脚本：`scripts/e2e-keys.mjs`（`npm run e2e:keys`）
> 前置：docker `dbstudio-mysql` 在 `127.0.0.1:13306`；缺 playwright-core / Electron / 产物则**跳过**（不算通过）

---

## 1. 为什么要「真 Electron」而不是浏览器 harness

`scripts/e2e-ui.mjs` 跑在纯 Chromium 里，穿不透两件事：

1. **原生菜单 accelerator** 在 macOS 上由 NSMenu 在 NSApplication 层拦截，根本不进渲染进程 —— 浏览器 harness 永远看不到这条路径。
2. **真实焦点流转**：React 事件批处理、复用宿主节点时 `autoFocus` 被跳过、弹窗抢焦点后 Esc 返回原焦点 —— 只有真窗口才有意义。

所以本清单把验收拆成**两段**：能自动化的进脚本（§2），自动化到不了的**单独列出、明确标「需人工」**，绝不把「测不到」写成「测过了」。

---

## 2. 自动化覆盖（K0–K9）

断言纪律：**「恰好一个」而不是「至少一个」**；每个「不触发」断言都必须配一个**会触发**的对照，否则断言没有证伪能力。

| 段 | 焦点 | 断言要点 |
|---|---|---|
| K0 | 准备 | 建连 → 拉 schema → 展开树 → 双击开表；状态栏「定位键：有 / 可写：是」；**非只读连接下不得出现只读横幅** |
| K1 | 树 | ⌘T 恰好 +1 标签；⌘W 恰好 −1；树里 ⌘F **不**误开网格查找条（跨层不串） |
| K2 | 网格 | ⌘F 恰好开 1 条查找栏；Esc 关；F12 开/关列定位浮层；⌥0 设 NULL（脏单元格 +1）且**再按一次幂等清除** |
| K3 | 单元格输入 | ⌘E 在「字面量 / SQL 表达式」间往返；**组合期 Esc 不退出编辑**（对照：普通 Esc 退出）；**组合期 Enter 不提交**（对照：普通 Enter 提交并退出） |
| K4 | SQL 编辑器 | ⌘R 出结果页签且**不是错误页签**；⌘/ 加行注释；⌘⏎ 执行选中；⇧⌘X 出「执行计划」页签 |
| K5 | 弹窗 | ⌘, 开偏好设置；**模态打开时 ⌘T 不在背后新建标签**；**组合期 Esc 不关弹窗**（对照：普通 Esc 关） |
| K6 | IME 矩阵 | 命令面板：先钉「有**真实**候选项」，再断**组合期 Enter 不执行**（对照：普通 Enter 执行、面板关闭）；树上**组合期 Backspace 不弹「删除表」**（对照：普通 Backspace 弹） |
| K9 | 只读连接 | 只读横幅 + `data-reason=read-only-conn`；状态栏「定位键：有 + 可写：否（只读连接）」；保存/导入禁用；双击单元格不进编辑；树右键「删除表」禁用**且带原因** |
| K8 | 控制台 | 全程零 `console.error` |

### 2.1 定位纪律（血泪）

- **树的定位必须走「连接 → 库 → 对象」三级**，不能只按表名。
  - 两条连接指向**同一个 MySQL 实例**，「连接可见的库」= 实例上全部库 ⇒ `ro_orders` 在两条连接下**各有一份**。
  - fixture 上还累积着历史 e2e 跑出来的库 ⇒ `orders` / `src` 这类通用表名在几十个库里都有（实测树 **287 行**）。
  - 只按表名 `.first()` 会命中**别的库 / 别的连接**里的同名表，断言红绿全部失去意义。
  - 实现：`findObjectRow(connName, dbName, tableName)`，靠 `.tree-row` 的 `data-node-kind` / `data-node-depth` **语义钩子**逐级收敛（一次 `evaluate` 批量取，不逐行往返）。
- **连接节点的标签是 `cfg.name`，不是 `cfg.id`** —— 拿 id 去匹配会**静默**定位失败（踩过）。
- 组合期（IME）场景用**合成 KeyboardEvent（显式 `isComposing: true`）**验证守卫；对照必须用**真实按键**（合成事件在「提交 / 执行」这条路径上是另一种输入源）。
- `.ws-tab` / `.statusbar` 暴露 `data-conn-id` 与 `data-readonly` / `data-conn-readonly`：把「判定输入」摆到 DOM 上，否则「只读没生效」这类缺陷肉眼分不清是漏读字段还是选错节点。

### 2.2 已知的环境注意点

- fixture 上会累积 `e2e_*` 临时库（脚本 kill / 中断时 `finally` 未跑完）。**不影响结论**，但会让树变长、脚本变慢。需要清理时按前缀手工删：`e2e_app_*` / `e2e_ddl_*` / `e2e_keys_*` / `e2e_tr_*`。
- 本机跑过一次后立即改脚本再跑，务必先确认上一次 Electron 进程已退出（脚本开头已自带 `pkill`）。

## 3. 需人工验收（自动化覆盖不到，必须手按）

> 以下项 CDP 注入的按键**进不去**对应路径。请逐条手按并在本文件对应行打勾。

- [ ] **原生菜单 accelerator**（⌘N / ⌘S / ⌘W / ⌘K / ⌘, / ⇧⌘R / ⌘0 / ⌃Tab…）
      —— 由 NSMenu 在应用层拦截，`page.keyboard.*` 走 CDP，测不到。
- [ ] **真实中文输入法（拼音候选）下的 Enter / Esc / Backspace**
      —— 需在单元格编辑框、SQL 编辑器、树、命令面板各按一遍；确认候选词操作**不会被**当成「提交 / 关闭 / 删除」。
- [ ] **⌘C / ⌘V / ⌘A / ⌘Z** 在网格与 SQL 下的表现（与系统 role 的优先级）。
- [ ] **五焦点 × 全命令的完整矩阵**
      —— 本脚本只覆盖每个焦点的**代表性**命令；完整「动作—入口—快捷键—目标对象」表见 `docs/product/ACTION-CATALOG-自动生成.md`（由 `npm run gen:actions` 从 `action-catalog.ts` 生成，改键必须同步）。

## 4. 运行方式

```bash
npm run build        # 需要最新产物
npm run e2e:keys     # 或 npm run e2e:keys:build 一步到位
```

失败时脚本会打印**现场截图路径**（`/tmp/e2e-keys-failure.png`）与**树的实际展开结构**，用于区分「真的没做」与「脚本选错了节点」。
