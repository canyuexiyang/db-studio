## 0. 本轮做了什么、没做什么

**做了**：逐个读 `scripts/e2e-ui.mjs`、`scripts/e2e-keys.mjs`、`docs/design-mockups/verify.mjs`、`scripts/verify-traffic-lights.mjs` 的断言体，判断每个检查项是否有**能变红**的断言，并回填到下表。

**没做**：本轮**没有执行任何门禁**（没有起 dev server、没有起 Electron、没有连 fixture），也没有做任何人工目视比对。因此下表的「本轮结论」是**静态覆盖判定**，不是「本轮实测通过」。

> ⚠️ 口径：「脚本里有断言」≠「断言当前是绿的」，更 ≠「界面观感合格」。后者需要实际跑一遍 + 人工看图，见 §4 的执行建议。

### 0.1 结论标记

| 标记 | 含义 |
|---|---|
| **已覆盖** | 脚本中存在针对该检查项的断言；错误实现会让它变红。括注断言名与脚本行号 |
| **部分覆盖** | 有相关断言，但不覆盖该场景的关键条件（不同宽度 / 另一主题 / 行高档位 / 标签数量） |
| **未覆盖（需补断言）** | 代码里有实现，但没有断言。属于**可自动化而未做**，不是「测不了」 |
| **未覆盖（需人工）** | 脚本原理上到不了（NSMenu 层、真实 IME、视觉观感、辅助技术、像素级观感） |
| **前置未就绪** | 依赖 T46/T47 的界面还没交付，没有可核验的对象 |

### 0.2 三个脚本各自能测什么（先划清能力边界）

| 脚本 | 运行环境 | 能测 | 测不到 |
|---|---|---|---|
| `scripts/e2e-ui.mjs`（`npm run e2e:ui`） | 有头 Chromium + vite dev + **demo 后端**（`:120` 固定 1440×900） | 渲染层行为、DOM 结构、计算样式、帧间隔 | 原生菜单、真实 IME、真库、非 1440 宽度、观感 |

## 4. 本轮实际观察到的问题（仅限文档/脚本/代码可确认部分）

> 以下每条都能用给出的路径复现判断；**不含**任何「看起来别扭」的主观描述。

1. **任务清单里 T48 自己写错场景数**：总表 `:135` 写「视觉与可用性核验清单（**7 项场景**）」，而同文件 `:694-703` 的表格是 **8 行**，调研报告 §8.3（`:451-460`）同样是 8 行。缺的那一项应是「可访问性」。

2. **1280 这条场景没有对应的断言宽度**：`e2e-ui.mjs:120` 写死 `viewport: { width: 1440, height: 900 }`，全脚本无 `setViewportSize`。而应用默认窗口恰是 1280×800（`window.ts:215-216`）——**验收尺寸与实际默认尺寸不是同一个**，1280 下的布局从未被断言过。

3. **行高三档只有纯逻辑单测**：`core-grid-view/src/index.test.ts:31-33` 覆盖 24/28/32 数值，但 `e2e:ui` 里没有任何切换行高的步骤。同时 `DataGrid.tsx:2234` 的 `canvas 高度 = rowCount * rowHeight` 是硬约束（注释 `:2537` 也这么写），却没有任何断言验证「滚到第 N 行时该行 top == N*rowHeight」。

4. **T18 的菜单键盘可达性没有测试**：`renderer/src/ui/useMenuBehavior.ts` 实现了视口钳制（`:66-74`）、↑↓/Home/End（`:104-120`）、Esc 返回原焦点（`:98-102`），但 `ui/` 目录下只有 `imeGuard.test.ts`；`scripts/` 里方向键相关的断言全部落在网格选区（`Alt+ArrowUp` / `Shift+ArrowDown`，`e2e-ui:1427-1452`、`:1707`），**没有一条针对菜单**，Home/End 零命中。**属于「交付了能力、没交付回归网」。**

5. **帧率门禁在 headless 下恒真**：`e2e-ui.mjs:540` 是 `HEADLESS ? true : fpsPass`。CI 只要设了 `DB_STUDIO_UI_HEADLESS=1`，「大结果 / 滚动性能」这条场景就变成**永远通过**。同理 `p95` 与 `droppedPct` 只打印（`:541`），不参与判定——与报告 §12.1「要看长帧」的要求只对了一半。

6. **可访问性断言极薄**：直接断言只有 `aria-label` **1 条**（`:2250`）+ 禁用原因 **2 条**（`:2282`、`e2e-keys:821`）；另有 `e2e-keys:436/439` 把 `[aria-label="定位列"]` 当**选择器**用（间接依赖可读名称，但不是断言「名称正确」）。「控件有名称」是 8 个场景里覆盖最薄的一项，focus ring 零断言。

7. **`verify.mjs` 只保证「图画对了」，不保证「画得好」**：它对筛选布局（`:144-148`）、详情注释（`:181-187`）有断言，其余全靠人工。这是设计意图（AGENTS.md 说「人工比对」），但清单里必须写明，否则容易被当成「双主题已自动化验收」。
