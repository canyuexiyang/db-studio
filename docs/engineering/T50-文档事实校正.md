```bash
$ git rev-parse v0.6.0^{commit}

$ git cat-file -p v0.6.0 | head -3

tag v0.6.0
$ git log --oneline -3
e9aac90 (HEAD, tag: v0.6.1, tag: v0.6.0) v0.6.1：P0 热修 …
```

## 7. 另需记录：别名有四处（AGENTS.md 的「三处」已过期）

> 这一节**只记录事实，不改工程约定**。

### 7.1 四处配置

| # | 文件 | 形式 | 匹配语义 | 行号 |
|---|---|---|---|---|
| ① | `tsconfig.json` | `compilerOptions.paths` 对象 | **精确匹配**（TS `paths` 不做前缀匹配） | `:20-46` |
| ② | `apps/desktop/renderer/tsconfig.json` | `paths` 对象（`baseUrl: "../../.."`） | 精确匹配 | `:21-45` |
| ③ | `vitest.config.ts` | `resolve.alias` **对象** | **前缀匹配**，按 key 插入顺序 | `:12-45` |
| ④ | `apps/desktop/vite.main.config.ts` | `CORE_ALIAS` 对象 | 前缀匹配，按插入顺序 | `:18-…`（`:76` 使用） |
| （附） | `apps/desktop/renderer/vite.config.ts` | `resolve.alias` **数组 + 正则 `$`** | 声明顺序 + exact 正则 | `:104-116` |

需要**同步维护**的是 ①②③④ **四处**；末尾那行不计入「必须同步」的原因是它用数组 + `^…$` 正则，**天然不受顺序影响**，不是漏掉。

`AGENTS.md:21` 原文：

> `@dbstudio/*` 别名在**三处同步维护**：根 tsconfig `paths`、`vitest.config.ts` alias、renderer tsconfig。新增包时三处都要加…

漏掉的是 **`vite.main.config.ts`**。后果：主进程构建时新包没有 alias → 走 `node_modules` 或直接 `UNLOADABLE_DEPENDENCY`。`docs/RELEASES.md:104` 已经记过这件事（「AGENTS.md 说的"三处"实为四处」），但 `AGENTS.md` 本身没改；`vitest.config.ts:18-19` 的注释里也仍复述「三处」。

### 7.2 子入口必须排在同名主入口之前

规则：**带 `/xxx` 的子入口，必须排在同名主入口之前**。原因是对象形式的 alias 做前缀匹配，主入口先命中会把 `@dbstudio/core-history/snippet-name` 拼成 `…/src/index.ts/snippet-name`。

| 配置 | 当前顺序 | 结论 |
|---|---|---|
| `vite.main.config.ts` | `core-history/snippet-name`（`:28`）在 `core-history`（`:31`）**之前** | ✅ 正确 |
| `renderer/vite.config.ts` | 数组 + `$` 正则，exact 规则在前（`:104-116`） | ✅ 天然安全 |
| `vitest.config.ts` | `core-history/snippet-name`（`:21`）在 `core-history`（`:24`）之前 ✅ | ✅ 这一对正确 |
| `vitest.config.ts` | **`core-sql-editor`（`:37`）排在 5 个子入口（`:38-42`）之前** | ⚠️ **顺序反了** |
| 两份 tsconfig | 主入口在子入口之前（根 `:37` 后 `:38-42`；renderer `:28-33`） | ✅ 无影响——TS `paths` 是精确匹配，与顺序无关 |

**为什么这个反序没炸**：`apps/desktop/renderer/src/editor/sqlEditorCore.test.ts:16` 是 `import type { SqlDiagnostic } from '@dbstudio/core-sql-editor/lint'`——**纯类型导入，编译后消失**，运行时不会走 vitest 的 alias 解析。一旦有人写值导入（比如在某个 `.test.ts` 里 `import { formatCount } from '@dbstudio/core-sql-editor/facts'`），vitest 就会尝试解析 `…/src/index.ts/facts` 并失败。

**这也解释了为什么「typecheck 与单测都发现不了，只有 build 才炸」**：typecheck 走精确匹配，单测只有在值导入子入口时才踩到；`vite build` 一定会踩。**判据不是「有没有跑门禁」，而是「有没有以值导入子入口」。**

### 7.3 建议动作

1. `AGENTS.md:21` 改为「**四处**（根 tsconfig / renderer tsconfig / vitest / vite.main；renderer vite 用数组+正则，无需顺序纪律）」，并补一句「**子入口必须排在同名主入口之前**」。
2. `vitest.config.ts:37` 的 `core-sql-editor` 移到 5 个子入口之后（顺序对齐 `vite.main.config.ts`）。**这是配置修改，不在本任务范围内，仅记录。**
3. 新增包时按 `vite.main.config.ts` 的顺序为模板抄。
