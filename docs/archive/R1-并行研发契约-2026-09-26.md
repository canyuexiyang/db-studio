## 〇、全局纪律（每个代理都必须遵守）

1. **文件所有权**（见 §二）：只能改你名下的文件。改了别人的文件 = 集成失败。
2. **禁改共享管线**（主控已预写，改了会撞车）：
   - `apps/desktop/src/shared/ipc-channels.ts` / `.cjs` / `renderer-types.ts`
   - `apps/desktop/src/preload/preload.cjs`
   - `apps/desktop/renderer/src/backend.ts`
   - `apps/desktop/src/main/ipc-handlers.ts`、`object-meta.ts`（object-meta 的**函数体**除外，见 §三.2）
   - `packages/core-export/src/index.ts` 的 `ExportFormat/ExportTextOptions` 类型、`transfer-manager.ts` 的请求类型
   - `apps/desktop/renderer/src/App.tsx`（**所有人禁改**，见 §一.1）
   - `apps/desktop/renderer/src/styles.css`（**所有人禁改**，见 §一.2）
3. **App.tsx 接线**：需要 App 层状态/回调的功能，在最终报告里写「App 集成说明」：精确到 import 行、需要新增的 state/callback、需要改哪个 JSX 节点。主控在集成阶段统一应用。
4. **样式**：不碰 styles.css。新样式写进自己名下目录的独立 css 文件并在组件里 `import './xxx.css'`（集成时主控合并回 styles.css）。选择器前缀用模块名（`.grid-*`、`.tree-*`、`.sql-*`、`.xf-*`、`.shell-*`），复用既有 token（`var(--bg)`、`var(--accent)`…），**禁止紫色系**，**图标一律 `ui/icons.tsx`**（禁 emoji），颜色跟 currentColor。
5. **新逻辑优先做成 core 包内纯函数 + 同目录 `*.test.ts` 单测**（core 包不依赖 Electron/React）。**禁止新建 npm 包**（避免三处 tsconfig alias 同步），新模块放进既有包。
6. 性能红线：滚动/编码热路径零对象分配、绝不 `decodeAll()`；大组件 lazy 化维持既有模式。
7. 完成定义：`npm run typecheck` 两套全绿 + 自己新增/改动的 `*.test.ts` 用 `npx vitest run <路径>` 跑过 + 每个功能在最终报告里有「实现说明 + 验收对照」。
8. 注释中文、写「为什么」；删除代码连注释一起删；文案简体中文。
9. 先读代码再动手：你的每个功能都可能已有部分实现（见 §三 各条「现状」），**合并优化而不是重复造**。

## 一、两个特殊政策

### 1. App.tsx = 主控独占
六个代理都接不上它。所有 App 级需求走「App 集成说明」。为了让这条路可行，设计组件时：
- 新状态尽量收在组件内部（DataGrid 内部管搜索/列宽/换行，localStorage 持久化）。
- 需要宿主提供的数据用 props 传入，需要回调宿主的用 `onXxx?` 可选 props（宿主没接时功能静默降级，不许崩）。
- 组件可以直接 `import { pickBackend } from '../backend'` 自取后端（App 传 props 不便时），demo 降级天然可用。

### 2. styles.css = 主控独占
新样式进自有 css 文件（§〇.4）。集成时主控合并。
