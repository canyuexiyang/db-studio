## 0. 规范地位与使用方式

### 0.1 唯一性

**🔴 强制**：本项目只有一套视觉语言，称为**中性精修**：macOS 原生的克制感 + DSH 案例验证过的
中性灰层级、横向分隔、反色主按钮和浮层尺度。

- 不再新增第二套配色、第二套圆角、第二套字体、第二套图标或第二套组件库。
- `docs/design-mockups/dsh-ui-case/` 是**视觉基线**，不是生产代码：其中的 `--dsw-*` 令牌、
  多 CSS 文件结构、16px 细线图标只用于说明观感，**不得原样复制到 `apps/desktop/renderer/`**。
- 生产样式只落在 `apps/desktop/renderer/src/styles.css`；生产图标只从
  `apps/desktop/renderer/src/ui/icons.tsx` 取。
- 任何“这个页面特殊，所以用另一套颜色/圆角/按钮”的做法都视为违规，走 §12 的例外流程。

### 0.2 与既有文档的关系

- `AGENTS.md` 的**红线、窗口约束、工程命令、性能纪律**仍然最高优先；本规范只收口视觉、
  组件、前端代码组织与文档要求。
- 本规范与 `AGENTS.md` §六 冲突时，视觉与组件细则按本规范；红线与工程约束按 `AGENTS.md`。
- PRD 的 §6.x 功能口径、`docs/engineering/` 的实测结论仍然有效；本规范不改变功能语义。
- PRD 的视觉/交互章节若与本规范冲突：**功能与验收按 PRD，视觉与组件尺度按本规范**；
  两者都必须服从 `AGENTS.md` 的红线与窗口约束。
- 旧版 `AGENTS.md` §六 的 Apple 精修 token 表是**迁移前基线**，不再作为新代码依据。

## 1. 设计原则

**🔴 强制**：以下原则是评审前提；不是“尽量”。

1. **快是产品定义，不是性能指标**：任何视觉方案都不能让“连接 → 定位表 → 查改数据”变慢。
2. **中性优先**：界面靠层级、留白和字重组织信息，不靠颜色堆叠；颜色只表达状态和可操作。
3. **一个视图一个主操作**：主按钮只能有一个；其余动作降级为次按钮、幽灵按钮或图标。
4. **状态必须可区分**：NULL / 空串、脏单元格 / 已保存、可写 / 只读、空表 / 筛选无结果 / 断线，
   四种对立状态必须在视觉上分得开。
5. **内容不透明**：玻璃只用于侧栏、浮层等导航/临时层；表格和正文必须不透明，保证可读性。
6. **克制地圆**：圆角按层级 4 / 8 / 12 / 16，不搞全站 8px，也不搞全站胶囊。
7. **可键盘、可退出**：所有模态有 Esc、遮罩、取消三条退路；所有图标按钮有 aria-label/title。
8. **不做假交互**：按钮必须有响应；不可用必须说明原因；不出现点了没反应的控件。
9. **中文界面**：UI 文案只做简体中文；数据库标识符、SQL、快捷键符号保持原样。
10. **不引入第三种风格**：所有新页面都能在视觉上并入现有工作台，而不是像另一个产品。

## 2. 视觉基线

### 2.1 基线定义

**🔴 强制**：视觉基线以 [`docs/design-mockups/dsh-ui-case/`](../design-mockups/dsh-ui-case/) 的
工作台、SQL 查询、命令面板、写入预演四个界面为准，遵循以下可迁移到生产的特征：

- 主内容白/近黑，侧栏用低对比中性灰；不靠大面积色块分区。
- 横向分隔线为主，几乎不画竖线；表格不使用斑马纹。
- 主按钮反色（浅色黑底白字 / 深色白底黑字）；蓝色只给链接、焦点和选中条。
- 表头 11px 等宽、数据 12px、正文 13px；数字列 `tabular-nums`。
- 状态徽章是“14% 状态色底 + 55% 混色文字”，不是直接拿状态色写字。
- 浮层用 0.5px 描边 + 轻阴影 + 12/16 圆角；菜单内边距 4px，行高 30。
- 所有图标线性、`currentColor`，无 emoji。

### 2.2 与生产实现的差异

**🟡 建议**：像素级不要求与样张逐点一致，以下差异是允许且已确认的：

- 生产继续使用 `ui/icons.tsx` 的 24 viewBox、2/2.4/2.6 线宽图标；样张的 16 viewBox / 1.5
  细线图标**不进入生产**，避免全站图标重画和混用。
- 生产的标准行高是 **32px**（紧凑 28 / 宽松 36）；样张中的 36px 是“宽松档”展示，
  不把 36 作为唯一默认。
- 生产右栏默认 **320px**；样张的 320 是目标值，现有 280 在迁移时一起调整。
- 生产按钮/标签字号按 §4 的字号阶梯，不引入 10.5 / 11.5 这类新档位。

> 这些差异只影响“密度和图标细节”，不改变中性精修的层级、颜色角色与交互语言，
> 因此不构成第二种风格。

## 3. 设计令牌

### 3.1 唯一来源

**🔴 强制**：

1. 颜色、字体、间距、圆角、阴影、动效、尺寸的数值只定义在
   `apps/desktop/renderer/src/styles.css` 的 `:root`。
2. 组件样式只能通过 `var(--token)` 引用，不允许写 `#hex`、`rgb()`、`hsl()`、具名颜色。
3. 新增 token 必须同时写入浅色 `:root`、深色 `[data-theme='dark']` 和媒体查询兜底块；
   三处键集合与值必须一致（`designTokens.test.ts` 已门禁）。
4. 不允许引用未定义 token；新增 `var(--x)` 必须确认 `x` 在 `styles.css` 的 `:root` 有定义。
   不允许用 `var(--x, fallback)` 给新代码兜底——兜底会把“token 写错”藏起来。
5. 新增 token 后同步更新 `theme/designTokens.test.ts` 的棘轮/幽灵 token 断言（如涉及）。
6. 组件内联 `style` 只允许做动态几何（宽度、位移、CSS 变量），不允许写颜色和字体。
   `--sidebar-w` / `--detail-w` / `--row-h` / 树缩进 `--depth` 由布局或密度状态写入根节点/行内 style，
   属于该例外，不视为硬编码。

### 3.3 颜色使用规则

**🔴 强制**：

1. **主按钮用反色**：`background: var(--primary-fill); color: var(--primary-ink)`，
   不使用 `--accent` 作为主按钮底色。
2. **强调色只给**：链接、focus ring、选中行左条、信息徽章/标记、少量可点击强调。
   不用于大面积背景、标题、表格边框。
3. **状态色只表达状态**：`--ok/--warn/--error` 不做装饰色；状态徽章按 §7.10 公式。
4. **禁止**紫色、紫蓝渐变、彩虹描边；禁止 `filter: invert()` 做深色。
5. 状态色文字必须经过混色（§7.10），或使用 `--ok-text` / `--warn-text`；
   不直接拿 `--ok/--warn` 当正文文字色。
6. 浅色 `--text-dim` 的对比度约 3.7:1，只允许用于标签/时间/辅助说明；
   表格数据用 `--text` 或 `--text-2`，不允许用 `--text-dim` 承载可读数据。
7. 深色下不使用纯黑 `#000` 作页面底；浅色下不使用纯白之外的色块铺满内容区。
8. 浅色 `--accent` 在案例 `#4176E6` 基础上下调到 `#3B6EDC`（白底 4.72:1），
   以保证 12px 链接可读；这是同色相的微调，不视为新风格。
9. 浅色 `--warn-text` 使用 `#B25E00`（白底 4.67:1），不用案例中的浅琥珀做文字；
   状态色文字一律走 §7.10 的混色公式。
10. 12px 级文字对比度目标 ≥4.5:1；大字号/粗体 ≥3:1；`--text-caption` 只做装饰，
    不得承载“是否可写/是否出错/是否删除”等关键信息。
11. 状态不能只靠颜色表达：徽章/标签必须带文字，危险操作必须有图标或文案；
    深色/浅色/色觉差异下都要能区分。

### 3.4 主题规则

**🔴 强制**：

- 主题唯一权威是 `<html data-theme="light|dark">`；`public/theme-boot.js` 在首帧 CSS 前写入，
  防闪烁。
- 媒体查询 `prefers-color-scheme` 只作为 JS 失效兜底；两个深色块的 token 必须完全一致。
- 组件不得自己判断深浅色；不得写 `@media (prefers-color-scheme)` 的局部配色。
- 主题切换不得改变布局尺寸（不允许深色下边框变粗、行高变高）。
- 截图必须浅/深各一张；不能只交浅色。

## 4. 字体与排版

### 4.1 字体栈

**🔴 强制**：

- UI：`-apple-system, "SF Pro Text", "PingFang SC", sans-serif`。
- 数据/代码：`"SF Mono", Menlo, monospace`（token `--font-mono`）；中文回退 `PingFang SC`。
- 不引入外部字体、不下载 woff、不使用系统未安装的品牌字体。
- 数字列、金额、ID、时间必须 `font-variant-numeric: tabular-nums`。
- 代码/列名/键名使用等宽字体；说明文字、按钮、正文不使用等宽。

### 4.2 字号与行高

| Token | 值 | 用途 |
|---|---|---|
| `--fs-2xs` | 9px | kbd、极小标签（仅限非关键信息） |
| `--fs-xs` | 10px | 分区小标题、徽章内文字 |
| `--fs-sm` | 11px | 表头、状态栏、说明 |
| `--fs-base` | 12px | 表格数据、按钮、输入框 |
| `--fs-mono` | 11.5px | 等宽数据（ID、时间、SQL 行号） |
| `--fs-md` | 13px | 正文、身份条、详情正文 |
| `--fs-lg` | 14px | 对话标题、空态标题 |
| `--fs-xl` | 16px | 页面级标题（少用） |
| `--lh-ui` | 20px | 常规 UI |
| `--lh-body` | 22px | 正文段落 |
| `--lh-code` | 18px | SQL/DDL 代码 |

**🔴 强制**：

- 新代码只能使用以上字号；不新增 10.5 / 11.5 / 12.5 等中间档（`--fs-mono` 除外）。
- 正文不小于 12px；可读数据不小于 11px；`--fs-2xs` 不承载关键信息。
- 字重只用 400 / 500 / 600；标题/主按钮 500，强调标题 600，不用 700 以上。
- 行高必须成对定义，不靠浏览器默认；表格/按钮/输入框使用固定高度 + 居中，不靠 padding 撑。
- 中文正文不使用 `letter-spacing`；全大写分区标题用 `0.06em`；等宽数据用 `-0.01em`。

### 4.3 截断与换行

**🔴 强制**：

- 按钮文字 `white-space: nowrap`，永不竖排；空间不足时优先收起低频按钮，不折行。
- 说明文本、连接名、表名、列名可 `ellipsis`，必须给 `title` 或浮层全文。
- 数据网格单元格单行省略；完整值通过双击/右键“查看完整值”查看。
- SQL/DDL 代码块允许横向滚动，不自动换行（除显式“换行”开关）。
- 不允许用 `overflow: hidden` 把关键错误/原因裁掉。

## 5. 间距、圆角、描边与阴影

### 5.1 间距

**🔴 强制**：布局间距只用 4 / 8 / 12 / 16 / 24 / 32 / 48；`6px` 仍允许用于图标-文字、
按钮内间隙，`10px` 仅兼容既有控件，不再新增布局使用点。

| Token | 值 | 用途 |
|---|---|---|
| `--sp-1` | 4px | 图标与文字、紧贴间距 |
| `--sp-2` | 6px | 既有按钮/图标间距（兼容） |
| `--sp-3` | 8px | 控件内边距、列表行 |
| `--sp-4` | 10px | 既有工具栏内边距（兼容） |
| `--sp-5` | 12px | 区块内边距 |
| `--sp-6` | 16px | 面板内边距 |
| `--sp-7` | 24px | 大区块/空态 |
| `--sp-8` | 32px | 页面级留白 |
| `--sp-9` | 48px | 空态/引导 |

- 布局间距以 4 的倍数为基线；不要出现 7 / 9 / 13 / 17 这类随手值。
- 垂直节奏：工具栏 44、筛选条 38、表头 32、行 32、状态栏 28 由 token 决定，
  不要在页面里另写高度。

### 5.2 圆角

**🔴 强制**：按层级使用，不按“好看”随手定。

| Token | 值 | 用途 |
|---|---|---|
| `--r-xs` | 4px | tag、kbd、小徽标 |
| `--r-sm` | 8px | 按钮、输入框、tab、菜单项 |
| `--r` | 12px | 面板、菜单、抽屉 |
| `--r-lg` | 16px | 对话框、命令面板 |
| `--r-pill` | 999px | 状态徽章、胶囊筛选条件 |

- 不允许所有元素统一 8px；不允许胶囊化所有按钮。
- 表格本身不加圆角；表格容器可以 0；数据区是满宽面。

### 5.3 描边与阴影

**🔴 强制**：

- 内部行线/分隔线：`var(--hairline)` + `--border-subtle`（0.5px）。
- 面板外轮廓：`var(--border-w)` + `--border`（1px）。
- 输入框/可交互边：1px + `--border`；聚焦时 1px `--border` + 焦点光环。
- 浮层：0.5px 描边 + `--shadow-pop`；**不允许** border + 大阴影 + 高饱和背景三者叠加。
- 表格、工具栏、状态栏、详情正文**不加阴影**；阴影只属于浮层。
- 不使用彩色阴影（除了状态提示的极轻色底）。

### 5.4 动效

**🔴 强制**：

- 颜色/背景/边框过渡 120ms ease；浮层进出 160ms。
- 只过渡 `background-color` / `color` / `border-color` / `opacity` / `transform`；
  不过渡 `width/height/top/left` 等布局属性（拖拽分隔条除外）。
- 尊重 `prefers-reduced-motion: reduce`；开启时取消动画，保留最终状态。
- 不在滚动路径上做动画、阴影重算或对象分配。

### 5.5 z-index

**🔴 强制**：只使用以下层级；不写 9999。

| Token | 值 | 层 |
|---|---|---|
| `--z-sticky` | 2 | 表头/行号列的 sticky |
| `--z-header` | 3 | 表头最上层 |
| `--z-resizer` | 5 | 面板拖拽 |
| `--z-menu` | 50 | 菜单/浮层 |
| `--z-modal` | 100 | 对话框/命令面板 |
| `--z-toast` | 200 | Toast |

## 6. 布局与响应式

### 6.1 窗口骨架

**🔴 强制**：

- 三栏：侧栏（默认 240px，范围 180–520）+ 主区（flex）+ 详情（默认 320px，沿用现有 220–600 安全约束，
  折叠后 32px 竖条）。
- 主区自上而下：标签条 38 → 工具栏 44 → 筛选条 38（可选）→ 内容 → 状态栏 28。
- 内容区必须不透明；侧栏可用 CSS 毛玻璃作为原生玻璃降级，但不得让正文透明。
- 原生交通灯安全区 78px；`traffic-light-safe` 不得放内容；不得自绘窗口按钮。
- 面板分隔条 4px 命中区、1px 视觉线；拖拽时禁用全局选中。
- 所有 pane 常挂 DOM，用 `.hidden` 隐藏；禁止为了切标签卸载有状态的编辑器/网格。

### 6.2 固定尺寸

| Token / 项 | 值 |
|---|---|
| `--sidebar-w` | 240px（默认，范围 180–520） |
| `--detail-w` | 320px（默认；沿用现有 220–600 安全约束；折叠 32px） |
| `--tabs-h` | 38px |
| `--toolbar-h` | 44px |
| `--filter-h` | 38px |
| `--grid-toolbar-h` | 34px |
| `--header-h` | 32px |
| `--row-h` | 32px（紧凑 28 / 宽松 36） |
| `--status-h` | 28px |
| 命令面板 | 640px 宽，最大 560px 高 |
| 写入预演 | 760px 宽，最大 `calc(100vh - 96px)` |

**🟡 建议**：新增页面不要另起高度；若必须新增区域，先在 §6.2 增加 token，再写组件。

### 6.3 密度

**🔴 强制**：

- 密度只通过 `--row-h` 三档切换：紧凑 28 / 标准 32 / 宽松 36；用户选择要持久化。
- 默认标准 32；大表/高频浏览可用紧凑 28；宽松 36 只作为用户选项，不作为默认。
- 密度切换只影响行高和垂直内边距，不改变字号、列宽逻辑或虚拟滚动模型。
- 不允许单个页面私自改 `font-size` 来“塞下更多”；空间不够用列宽、省略和更多菜单解决。

### 6.4 响应式

**🔴 强制**：只支持 macOS 桌面，不做移动端；窗口最小 900×600，推荐 ≥1280。

| 宽度 | 行为 |
|---|---|
| ≥1440 | 完整布局：详情 320、所有 meta 可见 |
| 1280–1439 | 紧凑：详情 292、侧栏 218；隐藏工具栏 `meta-extra` |
| 1100–1279 | 窄：隐藏工具栏 meta；主工具栏低频按钮进入“更多”；查询页 SQL 工具栏保持单行，超出时用左右箭头横向滚动；标签/按钮文字不换行 |
| 900–1099 | 最小可用：侧栏 180、详情 240；主操作保留，说明文字省略；SQL 工具栏保持单行，左右箭头横向滚动 |
| <900 | 不支持；由窗口 minWidth 拦截 |

- 断点内不做字号缩放；不改变主按钮位置。
- 主操作（执行、保存、筛选）永不折叠成不可发现的状态；最多收成图标 + title。
- 查询工具条在 <1280 时优先把「格式化 / 保存文件 / 执行计划」收进“更多”，
  执行 / 执行当前 / 停止 / 库选择必须常驻；<1100 才允许工具条横向滚动。
- 表格横向滚动允许；列不换行、不堆叠。冻结列/行号列必须在。
- 详情栏在窄窗口优先折叠成 32px 竖条，不挤占主区到不可用。
- 弹窗宽度用 `min(760px, 100vw - 48px)`，高度用 `max-height: calc(100vh - 88px)`。

## 7. 组件与页面样式

> 本节所有尺寸和颜色都来自 §3、§4、§6；组件不得自造。未列出的新组件先按“最接近的既有组件”
> 组合，不新造一套控件语言。

### 7.1 页面骨架

**🔴 强制**：

- 每个主页面 = 身份/标题 + 工具栏 + 内容 + 状态栏；内容区是唯一滚动主体。
- 页面内不出现第二个主按钮；主按钮固定在工具栏右侧或对话框 footer。
- 页面级空态使用统一空态块（图标 + 标题 + 说明 + 主操作）；不在空白区放随机插画。
- 页面背景用 `--bg`；侧栏 `--bg-panel`；详情 `--bg-alt` 或 `--bg`（按层级）。
- 数据/工作台页面全宽、不加页面级左右 padding（内边距由工具栏/网格自己负责）；
  设置/表单页居中，内容最大 760px，页面内边距 24–32px。
- 不用大面积卡片把页面切碎；优先用分隔线、标题和留白。

### 7.2 按钮

**🔴 强制**：

| 类型 | 规格 |
|---|---|
| 主按钮 | 高 28、圆角 8、`--primary-fill` 底、`--primary-ink` 字、500 字重；一屏最多一个 |
| 次按钮 | 高 28、圆角 8、`--bg-elevated` 底、1px `--border` |
| 幽灵/图标 | 透明底，hover 才上 `--row-hover`；图标按钮 28×28 |
| 危险按钮 | `--error` 底、白字；只用于不可逆操作，配合二次确认 |
| 小按钮 | 高 26（工具栏密集区）/ 24（行内/菜单 footer） |

- 文案 12px、`white-space: nowrap`、`flex: 0 0 auto`，禁止收缩和竖排。
- 图标按钮必须有 `aria-label` / `title`；纯图标不承载唯一语义。
- disabled 用 0.42 透明度，并在 `title` 说明原因；不允许“禁用了但不解释”。
- loading 时按钮内显示 12px spinner + 文案，禁用重复点击；不用全屏 spinner 代替按钮态。
- 快捷键放按钮内 `<kbd>`，字号 9–10，不能挤占主文案。
- 一个视图只能有一个 `.is-primary`；对话框 footer 的危险主操作算该视图的主操作。

### 7.3 输入框 / 下拉 / 搜索

**🔴 强制**：

- 高 28（对话框 30）、圆角 8、1px `--border`、`--bg` 底、12px 字。
- 聚焦：1px 选中边 + 3px `--focus-ring` 光晕；不只靠颜色变蓝。
- 错误：1px `--error` 边 + 错误说明；错误文案在控件下方，不只用红色边框。
- 搜索框带左侧 14px 图标、右侧 kbd 提示（如 ⌘F）；placeholder 12px `--text-caption`。
- 数据库标识符/值输入用 `--fs-mono`；普通文本输入不用等宽。
- 下拉必须显式设置 `background/color`，否则系统原生 select 在主题切换时不重绘。
- 不用 placeholder 当唯一 label；表单必须有可见 label 或 aria-label。

### 7.4 标签页

**🔴 强制**：

- 标签条高 38，标签高 30，圆角 8；活动标签用 `--bg` + 1px `--border` + 轻阴影；
  非活动透明 + 文字 `--text-2`。
- 标签最多 190px；标签文字 `ellipsis`；关闭按钮 16×16，hover 才显形。
- 脏标签用 5px `--warn` 圆点 + `title` 写明未保存数量；不把脏状态塞进文字。
- 查询标签用终端图标；表/视图用对应图标；固定标签要有星标或明确标识。
- 支持键盘切换、关闭；关闭脏标签必须先确认；关闭全部后显示空态。
- 不把标签做成大胶囊/大卡片；不把标签条做成第二工具栏。

### 7.5 连接树

**🔴 强制**：

- 行高 28（连接行 30），圆角 8，水平内边距 8，层级缩进 15px。
- hover `--row-hover`；选中 `--bg-alt` + `--text`；**不用蓝底白字**。
- 连接/库/类别行可折叠；对象行单击选中/看详情，双击打开；键盘 Enter/⌘↓ 等价双击。
- 类别行字号 11 `--text-dim`；对象行 12 `--text-2`；连接行 13/500 `--text`。
- 计数用 15px 胶囊或 10px 文本；脏对象用 5px `--warn` 点；只读对象可加锁图标。
- 树搜索实时过滤；无结果必须显示“没有匹配的连接或表”，不能留空白。
- 右键菜单复用宿主分级菜单；不在树组件里另写权限判断。
- 不画贯穿全树的竖线；层级靠缩进和图标，不靠线条。

### 7.6 工具栏与身份条

**🔴 强制**：

- 高 44；左侧身份条：连接 / 环境 / 库 / 对象，四段常驻，环境用 18px 胶囊。
- 操作按钮居右；主操作一个；分隔线 1×18 `--border-subtle`；右侧 meta 仅放状态信息。
- 主工具栏按钮不收缩、按钮文字不换行；窄窗口用“更多”收低频操作，主操作不收。
- **SQL 查询工具栏是单行横向滚动例外**：控件多且都重要，`flex-wrap: nowrap`，空间不足时显示左右箭头（24×28）横向滚动；所有控件 `flex: 0 0 auto`，不得压缩徽标、隐藏按钮或换行；高度固定 44。
- SQL 工具栏顺序按使用频率：**执行全部 → 执行当前语句 → 执行计划 → 取消 → 库下拉 → 执行对象 → 连接目标 → 格式化 → 打开文件 → 保存文件 → 另存为 → 文件状态 → 保存片段**。
- 身份条文字 12–13；对象名用等宽/500；过长省略并给 title。
- 标准窗口（≥1100）主工具栏自身不滚动；SQL 查询工具栏用左右箭头滚动，箭头在无溢出时隐藏，到左/右端时对应箭头禁用；焦点落到被遮住的按钮时自动滚进视野。
- 环境标签：生产红、开发蓝、本地灰；颜色不能是唯一信息，文字必须存在。

### 7.7 筛选条件条

**🔴 强制**：

- 高 38；左侧“筛选 + 计数”，中间条件 chip，右侧“清空”；SQL 预览用等宽 11 省略。
- chip 高 24、圆角 8、1px `--border`；列名等宽、值按类型引用；删除按钮 16×16。
- 真值只有 `tab.filter`；条件条只从真值派生，不能持有第二份筛选状态。
- 草稿/未应用条件必须显式标记（“草稿：…”），不能伪装成已生效。
- 删除条件 = 改模型并重新查询；不是只藏徽标。
- 查询失败时回退到上一个模型，不显示“新条件 + 旧数据”的假一致。
- 无筛选时不凭空显示条件条；空条件不进入 WHERE。

### 7.8 数据网格

**🔴 强制**：

- 表头 32，数据行 32（28/36 可选）；列头 11px 等宽 `--text-2`；数据 12px。
- **只画横向分隔线**（`--hairline` + `--border-subtle`）；不画竖线、不用斑马纹。
- 表头 sticky，背景必须不透明；行号列 sticky 左；横向滚动时行号列不脱锚。
- 行 hover `--row-hover`；选中行 `--bg-alt`/`--row-hover` + 2px `--accent` 左条；
  单元格选中用 1px accent 内描边，不用大色块。
- 脏单元格：`--dirty-bg` 底 + 2px `--dirty-bar` 左条 + 主文字；保存后清除。
- 待删除行：`--error` 7% 底 + 删除线 + 行号垃圾桶；不能只靠文字提示。
- NULL 用斜体 `--null-text` 的 `NULL`；空串显示 `''`；两者必须视觉可区分。
- 数字右对齐 + tabular-nums；BIGINT 用文本存储/显示，不转 Number。
- 排序指示器只在排序列显示；三态排序（无/升/降）必须有文字或 aria 说明。
- 不在滚动路径上分配对象/拼字符串/做正则；虚拟滚动只渲染可视区 + 缓冲。
- 空表、筛选无结果、断线、加载中、错误、只读六态必须有独立占位块，不能一片空白。
- 列宽拖拽/双击自适应、冻结列、横向滚动、行号列、复制范围等既有行为不得回退。

### 7.9 详情面板

**🔴 强制**：

- 宽 320；头部 44；正文 16px 内边距；可折叠成 32px 竖条。
- 分区标题 10px uppercase `--text-dim`；`dt` 66px + `dd` 自适应；行高 20–22。
- 字段行：名称等宽 + PK/UQ/AI/NOT NULL 等小 tag；第二行类型 + 注释常驻。
- DDL 用 11.5px 等宽、`--bg-alt` 底、8px 圆角、最大高度 112–150；可复制。
- 详情面板不加阴影；只用左侧 1px `--border` 与外层区分。
- 折叠/展开不能丢失内容；折叠后要有明确展开按钮。
- 未选中对象时显示说明，不显示空白。

### 7.10 徽章与标签

**🔴 强制**：

- 徽章高 18（大号 20），圆角 999，字号 10，500 字重。
- 公式：`background: color-mix(in srgb, var(--c) 14%, transparent)`；
  `color: color-mix(in srgb, var(--c) 55%, var(--text))`；`--c` 取状态 token。
- 徽章前圆点 4–5px，颜色跟 `currentColor`；文字必须可读，不直接用状态色当文字。
- tag（PK/UQ/AI/NOT NULL/索引名）高 20、圆角 4、等宽 9；不用胶囊。
- 一个单元格最多一个状态徽章；多状态用图标 + title，不堆叠三个徽章。

### 7.11 菜单与浮层

**🔴 强制**：

- 菜单：12px 圆角、4px 内边距、30px 行高、12px 字、`--bg-elevated` 底；0.5px `--border` + `--shadow-pop`。
- 菜单项 hover 上 `--row-hover`；危险项用 `--error` 文字 + 图标，不做红色整行底。
- 菜单必须锚定触发按钮；超出视口时翻转/左移，不能贴边截断。
- 点击遮罩、Esc、再次点触发按钮均可关闭；关闭后焦点回到触发按钮（可键盘时）。
- 菜单项不得是“点了没反应”的占位；未接能力要禁用并给 title 原因。
- 不做多层嵌套菜单；复杂操作用对话框/向导。

### 7.12 命令面板

**🔴 强制**：

- 宽 640；输入行 52；结果最多 10 条；浮层 16px 圆角、0.5px 描边、`--shadow-pop`。
- 背景用 `--bg-elevated` + 毛玻璃（降级为不透明）；遮罩 24% 黑。
- 输入即筛；`↑↓` 选择、`↵` 执行、`Esc` 关闭；`: ` 命令、`@` 历史模式。
- 分组标题 10px uppercase；行 40；标题 12、说明 10；右侧 badge/kbd。
- 空结果显示“没有匹配项”，不能显示空白列表。
- 命令面板不得吞掉输入法组合键；IME 组合期不响应 Enter。
- 结果超过 10 条用滚动，不压缩行高到不可读。

### 7.13 对话框 / 写入预演

**🔴 强制**：

- 宽 760、16px 圆角、`--bg-elevated` 底、header 64、footer 62；`max-height: calc(100vh - 88px)`。
- 遮罩 24% 黑；打开时焦点进入第一个可操作控件；关闭后回到触发点。
- **三条退路必须有**：Esc（内层先处理）、点遮罩、明确的“取消”按钮。缺一不可。
- 标题说清动作与数量（“即将执行 3 条语句”），副标题给对象/影响；不要只写“确认”。
- 写入预演必须展示完整 SQL 原文（逐条可看）；摘要只是附加层，不能替代原文。
- 生产/不可逆操作必须表名门禁：输入精确表名才启用危险主按钮；空串不算匹配。
- footer 左侧放门禁/说明，右侧放取消 + 危险主按钮；主按钮文案包含数量。
- 不显示“跳过预览”“不再提示”等绕过红线的入口。

### 7.14 Toast / Banner

**🔴 强制**：

- Toast：深色浮层 `--toast-bg` + `--toast-ink`、12px、8px 圆角、`--shadow-pop`；
  成功 3.2s 自动消失，warn/error 常驻并可手动关闭。
- 同屏最多一个 Toast；新消息替换旧消息，不堆叠遮挡内容。
- 点击 Toast 正文复制全文；错误必须包含“原因 + 下一步”。
- Banner 用于页面级状态（断线、只读、截断、续跑），不替代 Toast；
  高度 30–40，左侧图标 + 文案 + 右侧动作。
- Banner 不得自动消失；修复后由状态变化移除。
- 不用浏览器 `alert/confirm/prompt`；统一用项目对话框。存量中仍在用 `window.confirm` 的
  关闭/删除入口是新代码的迁移项，不得再新增。

### 7.15 空态 / 加载 / 错误 / 只读

**🔴 强制**：

- 空态：图标 36–44 + 标题 14–16 + 说明 12 + 主操作；垂直居中，上下≥32。
- 加载：超过 1s 才显示骨架/加载态，避免闪烁；骨架用 `--bg-skeleton`。
- 错误：标题 + 原因 + 重试按钮；不要只 toast 后留白。
- 断线：显示“已断开”与重试；不能仍显示“可写：是”。
- 只读：显示原因（只读连接/无定位键/视图）；禁用写操作并给 title 原因。
- 筛选无结果与空表文案必须不同；筛选无结果给“清空筛选”。

### 7.16 表单 / 设置 / 向导页

**🔴 强制**：

- 连接编辑器、表设计器、偏好设置、导入导出向导都复用本节的壳层，不另起一套“卡片式后台”。
- 表单页最大宽度 760px，居中；字段 2 列（≥1100）或 1 列（<1100）；标签 11px `--text-dim`，
  输入 28–30px；字段之间 12–16px；分组之间用 `--border-subtle` 分隔，不用大卡片包一层。
- 设置页行高 40：左侧标题 12 + 说明 11，右侧控件；开关/下拉/按钮右对齐；不把设置项做成营销卡片。
- 表设计器/连接编辑器这类复杂表单用“左分区导航 + 中间字段表 + 右侧预览”的三段式；
  字段表沿用 §7.8（只横线、不画竖线）；DDL 预览沿用 §7.9 的代码块样式。
- 导入导出用 760px 对话框 + 步骤条（11px，当前步 `--text`，其余 `--text-dim`）；
  footer 固定“上一步 / 下一步 / 取消”，危险动作不在向导中途出现。
- 向导/表单不得嵌套模态；必须能在当前层完成取消/返回；未保存改动要拦截关闭（复用既有 gate）。
- 表单错误就近显示在字段下方；提交失败保留用户输入，不清空表单。

## 8. 交互反馈与状态

### 8.1 基础状态

**🔴 强制**：

| 状态 | 规则 |
|---|---|
| hover | 灰底浮起（`--row-hover`），不把边框变蓝；120ms |
| focus | `:focus-visible` 2px `--accent` outline，输入框另加 3px `--focus-ring` 光晕 |
| active | 背景再深一档（`--sel-bg`/`--row-hover`），不使用缩放动画 |
| selected | 行/树/标签选中态必须同时有底色和文字色变化；不只用 1px 边 |
| disabled | 0.42 透明度 + `title` 原因；不改变布局尺寸 |
| loading | 按钮内 spinner；区域加载用骨架；不阻塞整个窗口 |
| error | 状态色 + 文案 + 重试；不静默失败 |

### 8.2 键盘与焦点

**🔴 强制**：

- 所有可操作元素可 Tab 到达；图标按钮有 aria-label；焦点环不能为 `none`（除指针输入态）。
- Esc：先关内层菜单/浮层，再关对话框；对话框必须有 Esc 退路。
- `⌘K` 命令面板、`⌘T` 新查询、`⌘F` 网格查找、`⌘S` 保存预演、
  `⌘⇧F` 筛选、`⌘R`/`⌘⏎` 执行、`⌘.` 取消；新增快捷键必须注册并跑 `e2e:keys`。
- 全局快捷键不得在输入框/输入法组合期抢键；用 `isImeComposing` 守卫。
- 菜单/对话框关闭后焦点回到触发元素；Tab 不逃出模态。
- 树/表格/命令面板支持方向键；Enter 是“打开/执行”，Space 是“选中”（按组件语义）。

### 8.3 选择与编辑

**🔴 强制**：

- 网格选中行/单元格后，状态栏必须显示选中行数/格数；数据来自同一选择模型。
- 只提交被编辑的单元格，绝不整行覆盖（红线）；UI 不自己拼 UPDATE。
- 编辑态/脏标记/撤销重做必须按 tab 隔离；切换标签保留。
- 脏单元格视觉三件套：底、左条、保存按钮计数；缺一不可。
- 无主键/唯一键表只读；可编辑判定只问 `isEditable()`，UI 不自判。
- 空值写入、批量编辑、SQL 表达式必须有明确标识与预览。

### 8.4 异步与错误

**🔴 强制**：

- 所有异步请求有 loading 态；长于 1s 显示进度/骨架；可取消的操作必须真取消
  （KILL QUERY / kill utilityProcess）。
- 请求返回后必须有 alive/seq 守卫，防止旧响应写入新视图。
- 失败必须可见：Toast + 区域错误 + 重试；不能只 console。
- 不伪造成功：demo 后端每次返回新对象，不返回常量引用。
- 断线/重连：状态栏、Banner、网格空白区三处口径一致；不能“看起来可写但写必失败”。

### 8.5 破坏性操作

**🔴 强制**：

- 先预览 SQL 原文，再执行；不可跳过。
- 生产环境、删行、无 WHERE 更新、删表/删库必须有二次门禁；门禁输入精确名称。
- 危险按钮用 `--error`，文案包含对象/数量；取消是幽灵按钮。
- 只读连接/视图的写入口必须禁用并说明原因；守卫层仍是最后防线。
- 操作成功后按固定顺序：登记定位意图 → 刷新结构 → 最后 toast 成功回执。

### 8.6 反馈时序

**🔴 强制**：

- 点击 → 立即有视觉反馈（active/hover）；异步超过 150ms 才显示 loading（避免闪烁）。
- 成功回执不能覆盖刷新/定位的反馈；同一动作只保留一个主 Toast。
- 错误常驻，直到用户关闭或问题解决；不自动消失。
- 操作完成后焦点/滚动位置不跳；除非用户明确要求定位。

## 9. 代码组织

### 9.1 分层

**🔴 强制**：

```
packages/core-*            纯逻辑：无 Electron、无 React、无 DOM；可离线单测
apps/desktop/src/main      主进程：Node、窗口、IPC、驱动、worker
apps/desktop/src/preload   预加载：只暴露白名单 API
apps/desktop/src/shared    IPC 通道/共享类型
apps/desktop/renderer/src  React 渲染层：DOM、样式、交互
```

- 渲染层不得 import 主进程/Node 模块；包不得 import Electron/React/DOM。
- 新逻辑优先做成 `packages/core-*` 的纯函数，并在同目录写 `*.test.ts`。
- 渲染层按功能分目录：`grid/`、`tree/`、`editor/`、`workspace/`、`detail/`、
  `filter/`、`transfer/`、`designer/`、`database/`、`danger/`、`palette/`、`ui/`。
- 新功能目录至少包含：组件 `.tsx` + 纯逻辑 `.ts`（可无）+ 对应测试；不允许把逻辑全塞进 `App.tsx`。
- `App.tsx` 只做组合、跨模块状态和副作用接线；新增复杂逻辑必须下沉。

### 9.2 单一事实源

**🔴 强制**：以下内容只能有一个出处，禁止复制第二份：

| 内容 | 唯一出处 |
|---|---|
| 视觉 token / 组件样式 | `apps/desktop/renderer/src/styles.css` |
| 图标 | `apps/desktop/renderer/src/ui/icons.tsx` |
| DDL 构造 | `renderer/src/database/ddlTemplates.ts` |
| IPC 通道 | `apps/desktop/src/shared/ipc-channels.ts` |
| 快捷键/动作 | 既有快捷键注册表 + `npm run gen:actions` |
| 可编辑判定 | `core-mutation` / `core-schema-cache` 的 `isEditable()` |
| 筛选真值 | `tab.filter`（UI 只派生） |
| 脏单元格 | `GridDataSource` + `core-mutation` |
| 模态占用语义 | `workspace/singleModalGate.ts` |
| 布局宽度 clamp | `workspace/layoutClamp.ts` |

- 同一标识符出现在多处时必须钉成等式（如 owner/URL/版本），并加测试。
- 新增包时四处别名（根 tsconfig、vitest、renderer tsconfig、renderer vite）同步；
  对象形式别名的子入口必须排在同名主入口前。

### 9.3 CSS 组织

**🔴 强制**：

- 生产样式只写 `styles.css`；不新增 CSS Modules / styled-components / Tailwind /
  第二份全局样式表。
- `styles.css` 顺序：token `:root` → 浅色/深色 → 基础 reset → 骨架 → 布局 →
  通用组件 → 功能组件 → 页面特例。
- 新增样式块前先加 3–5 行“为什么”注释；不写“这里是按钮”的复述。
- 类名沿用模块前缀（§10.3）；新增前缀必须登记到 §10.3 的表。
- 禁止 `!important`（除覆盖第三方编辑器内部样式，需注释原因）。
- 禁止 `@import`；禁止在组件里写 `<style>`。
- 0.5px 发丝线只用于内部分隔；外轮廓用 1px。
- 修改 token 后必须跑 `npm test`（designTokens 守卫）和双主题截图。

### 9.4 React 规则

**🟡 建议 / 🔴 关键项**：

- 函数组件；新增组件一律命名导出，既有 `export default` 组件保留、不因风格统一而重写；
  不用 class 组件。
- Props 用 `interface XxxProps`；事件 `onXxx`；布尔 `is/has/can`；ref `xxxRef`。
- 派生数据用 `useMemo`，不要用 `useEffect` 同步 state；副作用只做外部同步。
- 依赖数组必须完整；禁止 `eslint-disable` 掩盖真实依赖问题（确需时写明原因）。
- 列表 key 用稳定 ID/全局行号；不用数组 index 做动态行 key。
- 所有订阅/定时器/请求在 cleanup 中释放；异步回调加 alive/seq 守卫。
- 组件不直接拼 SQL；不直接读文件系统；不直接访问 Electron API（走 backend/IPC）。
- 大组件按职责拆；单个渲染组件超过 ~400 行先找可下沉的纯逻辑。
- 懒加载组件（SQL 编辑器、连接编辑器、导入导出、表设计器）必须保留首屏外壳样式，
  避免懒加载间隙布局塌陷。

### 9.5 性能与体积

**🔴 强制**：

- 首屏 bundle ≤1.5MB 未压缩；`npm run check:bundle` 是门卫。
- CodeMirror 等重依赖只进 lazy chunk；首屏不出现 `cm-editor`/`autocompletion` 等特征串。
- 滚动/编码热路径禁止对象分配、正则、字符串拼接；只渲染可视区。
- 不在渲染层做全量 decode/materialize；只解可视区。
- 新依赖先跑 `check:bundle`；体积敏感的“锦上添花”依赖默认不加。

### 9.6 测试与门禁

**🔴 强制**：

- 纯逻辑与源码同目录 `*.test.ts`；`npm test` 覆盖 `packages/**` + `apps/**`。
- UI/交互改动跑 `npm run e2e:ui`；键盘改动跑 `e2e:keys`；DDL 改动跑 `e2e:ddl:real`。
- 新断言必须在错误实现上验证会红；demo 后端“恒真”的断言不算验收。
- 不能造出前置条件的断言宁可不写；不要写“不改代码也通过”的假绿。
- 修改全局并发/状态逻辑必须跑 `e2e:ui` + `e2e:keys` + `check:bundle`。
- 提交前至少：`npm run typecheck && npm test && npm run check:bundle`；改样式再加双主题截图。

### 9.7 依赖与别名

**🔴 强制**：

- 不新增 UI 组件库、图标库、CSS-in-JS、外部字体；需要时先提 ADR。
- 新依赖必须评估体积、许可证、Electron/Node 兼容和打包影响。
- `@dbstudio/*` 别名四处同步；漏一处会出现“typecheck 过但测试 fallback 到 node_modules”的隐性错位。

## 10. 命名

### 10.1 文件与符号

**🔴 强制**：

| 类型 | 规则 | 示例 |
|---|---|---|
| React 组件 | PascalCase `.tsx` | `DataGrid.tsx`、`SavePreviewModal.tsx` |
| Hook | `useXxx.ts` / `useXxx` | `useWorkspaceTabs.ts` |
| 纯逻辑 | camelCase `.ts` | `ddlTemplates.ts`、`tabOrder.ts` |
| 测试 | 与源码同名 `.test.ts` | `filterBarModel.test.ts` |
| 类型/接口 | PascalCase；Props 用 `XxxProps` | `GridColumn`、`TablePaneProps` |
| 常量 | UPPER_SNAKE | `TABLE_PAGE_LIMIT`、`SIDEBAR_W` |
| 函数 | camelCase，动词开头 | `loadTable`、`resolveEditability` |
| 布尔 | `is/has/can/should` | `isEditable`、`hasFilter` |
| 事件 | `onXxx` | `onSave`、`onCellEdited` |
| ref | `xxxRef` | `gridRef`、`dirtyGuardResolveRef` |

- 不用拼音命名；UI 文案中文，代码标识符英文。
- 类型导出优先 `export type` / `import type`。

### 10.2 令牌命名

**🔴 强制**：`--<类别>-<角色>[-<状态>]`，全小写连字符。

- 颜色：`--text-2`、`--border-subtle`、`--dirty-bar`；不带组件名。
- 尺寸：`--row-h`、`--tabs-h`、`--detail-w`；单位写在值里。
- 状态：`--sel-bg`、`--focus-ring`；不写 `--blue-1` 这类色名。
- 不新增 `--dsw-*` 前缀到生产；DSH token 只存在于设计案例。

### 10.3 CSS 类前缀

**🔴 强制**：新样式必须带模块前缀；新前缀登记到下表。

| 前缀 | 模块 |
|---|---|
| `app-` / `toolbar` / `statusbar` | 应用骨架 |
| `ws-` | 工作区标签/面板 |
| `tree-` | 连接树 |
| `grid` / `gd-` | 数据网格 |
| `fb-` / `fbbar-` | 筛选条 |
| `detail-` / `dc-` | 详情面板/字段 |
| `sql-` | SQL 编辑器/结果 |
| `ce-` | 连接编辑器 |
| `ob-` | 对象浏览 |
| `gs-` | 网格状态块 |
| `modal-` / `danger-` | 对话框/危险确认 |
| `palette` | 命令面板 |
| `toast-` | Toast |
| `pref-` | 偏好设置 |
| `tb-` | 工具栏 |
| `tr-` | 导入/导出/传输 |

- 状态类：既有 `.active` / `.hidden` / `.primary` 保留；新代码用 `.is-*` / `.has-*`，
  同一组件内不混用两套状态命名。
- 不新建无前缀的 `.card` / `.button` / `.title` 这类全局类。

### 10.4 data-testid

**🔴 强制**：

- 只用 kebab-case，语义稳定，不绑文案：`btn-save`、`pane-${id}`、`status-writable`。
- 常用前缀：`btn-`、`pane-`、`status-`、`menu-`、`input-`、`toast-`。
- e2e 用 data-testid / 语义角色，不靠 class 或精确文案；文案可以改，testid 不能随便改。
- 测试 id 不得包含临时数字/随机值；动态列表用业务键（表名、节点 key），不用 index。

## 11. 格式与注释

### 11.1 代码格式

**🔴 强制**（当前仓库无 ESLint/Prettier，按既有文件风格执行）：

- 2 空格缩进；LF；UTF-8；文件末尾换行。
- 单引号；语句末尾分号；多行对象/数组/参数尾逗号。
- 代码行软限制 120 列；注释和长条件可放宽，不为了断行破坏语义。
- 导入分组：Node 内置 → 外部依赖 → `@dbstudio/*` → 相对路径 → 类型导入；
  组间空行。
- 新增代码命名导出；既有 `export default` 保留（如 `ImageViewer`/`JsonTreeView`），
  重构时再统一，不为风格单独改文件。
- `import type` 用于纯类型；不要 `import { type X }` 与值混用时偷懒。
- 不写 `any`；边界用 `unknown` + 类型收窄；`as` 只用于已证明的边界。
- 不用非空断言 `!` 掩盖可能为空；确需时写注释说明不变量。
- 不用 `@ts-ignore`；确需时改 `@ts-expect-error` 并写明原因。
- 不提交 `console.log`（调试日志用 `console.warn/error` 且带原因）；不提交注释掉的死代码。

### 11.2 注释

**🔴 强制**：

- 注释用简体中文，解释“为什么”，不解释“这行做了什么”。
- 关键决策/红线/踩坑点必须有注释，引用 PRD/规范/实测章节号。
- 复杂函数前写 2–5 行意图、边界、失败模式；不写空泛的“处理数据”。
- 删除代码时连注释一起删；不留“旧实现”注释块。
- 不用 emoji 当状态标记（🔴/✅ 只允许出现在文档，不出现在 UI）。
- 文件头保留模块职责、关键约束、相关需求编号；新增文件按现有风格。

### 11.3 提交与评审

**🟡 建议**：

- 提交信息中文，格式：`type(scope): 简述`；type 用 `feat/fix/refactor/style/docs/test/chore`。
- 一个 PR 只做一类改动；视觉重构与业务修复分开。
- PR 描述写：改了什么、为什么、影响面、验证命令、截图（浅/深）。
- 评审先看红线，再看视觉一致性，最后看命名/格式。

## 12. 文档与变更

### 12.1 文档要求

**🔴 强制**：

- 新增/修改页面、组件、交互，必须同步更新以下之一：
  - 对应 PRD/REQ 的功能小节；或
  - 本规范（如果是新的通用模式）；或
  - `docs/design-mockups/`（如果是视觉样张）。
- 新增通用组件、token、CSS 前缀，必须更新本规范对应章节。
- 修改视觉基线（颜色、字体、行高、主按钮、布局尺寸）必须：
  1. 先改本规范；
  2. 出浅/深双主题截图；
  3. 跑 `e2e:ui`；
  4. 在 PR 写清“为什么现有规范不够”。
- 文档索引在 `docs/README.md`；本规范必须出现在索引里。
- 发版记录在 `docs/RELEASES.md`；视觉变更要在版本说明里单独列出。
- 注释/文档引用章节号，不引用“上面说的”；章节调整时同步搜改。

### 12.2 规范变更流程

1. 提 issue/PR，说明动机、影响范围、是否有实测依据。
2. 更新本规范（版本号 + 变更记录）。
3. 更新 token/组件代码与截图。
4. 跑门禁；评审通过后合并。
5. 旧值删除或标记 deprecated；不长期保留双份。

### 12.3 例外

**🔴 强制**：

- 任何偏离本规范的样式，必须在 PR 描述里写：哪条规则、为什么、影响范围、何时回收。
- 例外只允许局部、可回滚；不允许以“设计需要”为由新增第二套 token/组件库。
- 安全/性能/无障碍冲突时，优先红线与可访问性，再评审视觉妥协。

## 13. 迁移与门禁

### 13.1 迁移原则

**🔴 强制**：

- 本规范是**目标基线**；现有 Apple 精修样式是迁移前状态，不是第二套风格。
- 迁移按屏幕分批：一个屏幕内不允许同时存在旧蓝主按钮和新反色主按钮。
- token 层可以一次性切换（颜色/圆角/边框/尺寸），组件层按屏幕推进。
- 每批迁移必须：双主题截图 + `e2e:ui` + 人工比对；不做“一次性全站重做”的大爆炸。
- 迁移完成前，新代码不得复制旧值；旧值只允许通过现有 token 使用，并在注释标 `TODO(migrate)`。

### 13.2 迁移阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 采纳本规范；在 `styles.css` 落目标 token；更新 `AGENTS.md` 指针 | 文档评审；token 测试全绿 |
| P1 | 骨架尺寸：标签 38 / 工具栏 44 / 状态 28 / 详情 320 / 行高 32 | 1440/1280 截图；无横向溢出 |
| P2 | 工作台：表头 32、只画横线、选中/脏/删除态、反色主按钮、徽章公式 | `e2e:ui` + 双主题截图 |
| P3 | 查询/详情/筛选/命令面板/写入预演 | 对应 e2e + 截图 |
| P4 | 清理旧值、更新设计稿、补文档 | 全量 `npm run verify` |

### 13.3 提交前门禁

**🔴 强制**：

- `npm run typecheck` 全绿（根 + renderer 两套）。
- `npm test` 全绿；新增纯逻辑有测试。
- `npm run check:bundle` 通过（改依赖/首屏必跑）。
- 改 UI：`npm run e2e:ui`；键盘：`e2e:keys`；DDL：`e2e:ddl:real`。
- 改样式：`node docs/design-mockups/verify.mjs` 出浅/深截图并人工比对。
- 改 token：`designTokens.test.ts` 幽灵 token / 双深色块一致性必须绿。
- 不跑门禁就宣告完成，视为未交付。
