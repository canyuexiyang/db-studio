# @dbstudio/core-tree-view

库表树视图模型。

> 依据：PRD §6.2 / D1（展开记忆）/ Q2（按字段名搜表）

结构：**分组 → 连接 → 数据库 → 对象类型（表/视图/存储过程/函数）→ 对象**

## 为什么必须扁平化

树是嵌套的，虚拟滚动需要一维数组。`flattenTree()` 把**展开的节点**压成
`FlatNode[]`，渲染层只按 index 取 —— **不递归、不在渲染时算可见性**。

未展开的分支整段跳过，不构造不可见行。一个实例几百张表 × 多个库时，
这是唯一能撑住的形态。

## 展开记忆（D1）

- 首次：**展开到数据库层**（分组与连接开，库下的"表/视图/..."不开）
  —— 否则 128 张表会一次性糊在屏幕上
- 之后：记住用户展开过的节点，异步恢复
- 存的是**节点 key** 而不是下标 —— 库表顺序变化时下标会错指到别的节点
- 表被删了/改名了 → 旧 key 自然失效，**静默丢弃**（不报错，也不让树抖）

## 搜索

匹配表名/视图名/字段名，**保留祖先链**（否则搜到的节点无父可挂）。

### 拼音首字母

`dd` → `订单明细`。

⚠️ 实现口径：**显式汉字 → 首字母映射，只覆盖数据库领域常见字**。
不引拼音词典（几百 KB，与"首屏 bundle ≤1.5MB"硬约束冲突）。
也**不用 Unicode 区段猜首字母** —— 试过，会错：例如"单"(U+5355) 按区段落进 b 区，
实际是 d。**猜错比不支持更糟**，用户会以为功能坏了。未命中的字跳过，退化为子串匹配。

## 危险操作

`confirmLevelFor()`：删表/截断表 → 二次确认；生产环境（红色标签）→
再加一层，需手动输入表名。
