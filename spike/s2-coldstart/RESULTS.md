# Spike S2 结论报告：冷启动骨架（懒加载策略下 P50 能否 ≤1.5s）

> 验证性 Spike。实测日期：2026-09-21
> 环境：macOS 27.0 (26A428, Darwin 27.0.0) / Apple M5 Pro 15核 / 48GB / arm64 / Electron 44.4.3 (Node 24.21.0, Chromium 152.0.7977.130)
> 每组 5 次，按 PRD §7.2 取**第二次及以后**（首次受 Gatekeeper 校验影响不计入）。

---

## 0. 一句话结论

**冷启动 ≤1500ms 大幅可达 ✅，且余量极大。** 打包版（C3）P50 = **217ms**（进程内口径）/ **265ms**（spawn 口径），仅为预算 1500ms 的 **14~18%**。懒加载收益有限（省 ~30ms），因为 Electron 44 + M5 的启动基线本身就极快；**真正的优化重点不在懒加载，而在于别把启动路径做重**。

---

## 1. 三组实测（P50，n=5）

| 组 | 配置 | **P50（进程内 perf 口径）** | **P50（spawn 口径，含进程 fork）** | vs 预算 1500ms |
|---|---|---|---|---|
| **C1** | 朴素：启动路径同步 require `mysql2`+`pg`+`ssh2`+`node:sqlite` | **247 ms** | **297 ms** | ✅ 达标（余量 1203ms） |
| **C2** | 懒加载：空壳窗口，依赖按需 | **225 ms** | **269 ms** | ✅ 达标（余量 1231ms） |
| **C3** | **打包版**（C2 + electron-builder arm64 / asar 默认压缩） | **217 ms** | **265 ms** | ✅ **达标（余量 1283ms）** |

### 原始每次数据（供审计，单位 ms）

| 组 | 每次（perf 口径） | 每次（spawn 口径） |
|---|---|---|
| C1 | 267, 246, 247, 262, 238 | 317, 292, 297, 312, 288 |
| C2 | 239, 225, 210, 246, 211 | 288, 269, 259, 297, 261 |
| C3 | 211, 217, 214, 238, 219 | 264, 265, 265, 284, 270 |

> **两种口径说明**：`perf 口径` = 进程内 `performance.now()` 从模块顶部到首次 paint；`spawn 口径` = 外部驱动器从 `spawn()` 到结果落盘的墙钟时间，包含进程 fork/exec 开销。两者相差约 45~50ms，后者更贴近用户感知。**取 spawn 口径更保守，结论仍大幅达标。**

---

## 2. 阶段分解（P50，定位最贵环节）

| 阶段 | C1 朴素 | C2 懒加载 | **C3 打包** | 说明 |
|---|---|---|---|---|
| exec → 模块顶部 | 63 ms | 62 ms | **63 ms** | Electron/Node 运行时初始化，**固定成本，不可压缩** |
| 模块顶部 → `whenReady` | **59 ms** | 33 ms | **32 ms** | **C1 比 C2/C3 慢 26ms —— 这就是驱动 require 的全部代价** |
| `whenReady` → 窗口创建 | 43 ms | 47 ms | **44 ms** | |
| 窗口创建 → `did-finish-load` | 73 ms | 61 ms | **63 ms** | 渲染进程启动 + 首屏 HTML 解析 |
| `did-finish-load` → 首次 paint | 9 ms | 17 ms | **17 ms** | |
| **合计** | **247 ms** | **225 ms** | **217 ms** | |

**最贵的两块**：
1. **`exec → 模块顶部`（63ms，占 29%）** —— Electron 运行时初始化，**这是硬成本，懒加载也省不掉**。
2. **`模块顶部 → whenReady`（32~59ms）** —— 唯一能被懒加载影响的部分。

---

## 3. 懒加载收益量化（C1 vs C2）

| 项 | 值 |
|---|---|
| C1（全部同步 require）P50 | 247 ms |
| C2（懒加载）P50 | 225 ms |
| **懒加载节省** | **22 ms（约 9%）** |
| 其中驱动 require 实测耗时 | **~26 ms**（`moduleTopToWhenReady`：59ms → 33ms） |

### ⚠️ 与评审预估的重要偏差

TECH-REVIEW §5.1 称驱动懒加载是「**最大的一块**」，§7.2 也把它列为首要措施。**实测不支持这个判断**：

- 三个驱动（`mysql2` + `pg` + `ssh2`）+ `node:sqlite` 全部同步加载，**总共只花 26ms**。
- 原因：这些包在 M5 上的 JS 解析极快，且 `mysql2`/`pg` 是**纯 JS**（无原生模块编译/加载开销），只有 `ssh2` 带可选的原生加速（默认走 JS 实现）。
- **结论：懒加载仍应做**（26ms 是净收益，且能降低峰值内存），但**不应把它当作冷启动达标的关键路径**。真正的固定成本是 Electron 运行时初始化（63ms）+ 渲染进程启动（~107ms），共约 170ms，占打包版总耗时的 **78%**。

---

## 4. 打包与未打包的差异（C2 vs C3）

| 项 | C2（未打包） | C3（打包 / asar） | 差异 |
|---|---|---|---|
| P50（perf） | 225 ms | **217 ms** | **−8 ms（打包反而略快）** |
| P50（spawn） | 269 ms | **265 ms** | −4 ms |

**结论：asar 打包没有拖慢启动，反而略快 4~8ms**（符合 PRD §7.2 的判断——默认压缩不显著影响首次启动）。**不需要**关闭 asar。

> PRD §7.2 要求 `compression` 用默认而非 `maximum` —— 本次即采用 `normal`，实测无负面影响，该约束可保留。

---

## 5. 结论

### 5.1 「冷启动 ≤1500ms」判定：✅ **可达**，无需修正

- 打包版 P50 = **217ms**（perf）/ **265ms**（spawn）
- 余量约 **1283ms**（85% 的预算没用掉）
- **不需要**按评审建议改为 ≤2.0s

### 5.2 但必须说明的边界（防止将来被打脸）

1. **探针是空壳应用**，没有 React、Zustand、CodeMirror、三栏布局、连接树。真实应用的启动会显著更慢——尤其是 **CodeMirror 懒加载前的首屏 JS 体积**和 **React 首次提交**。
2. **预算的真正风险点不在本 Spike 测到的范围**：217ms 里约 170ms 是 Electron 固定成本，留给应用的只有 ~47ms 才不超 1500ms——**看似余量巨大，但真实应用很容易在首屏塞进 1~2MB 的 JS**。
3. **建议把 1500ms 预算拆成子预算**（便于工程验收时定位回归）：
   | 子项 | 建议预算 |
   |---|---|
   | Electron 运行时 + 窗口 + 首屏 paint（本 Spike 实测基线） | ≤ 400 ms |
   | 应用首屏 JS 解析 + React 提交 | ≤ 700 ms |
   | 历史库打开 + 配置读取 + schema 快照加载 | ≤ 400 ms |
   | **合计** | **≤ 1500 ms** |
4. **测量环境限制**：脚本化启动时 macOS 沙箱初始化会失败导致 GPU 进程崩溃，已加 `--no-sandbox --disable-gpu-sandbox --in-process-gpu` 让进程存活。这些开关**不参与渲染路径**，对启动链路耗时影响可忽略，但**本 Spike 未测「真实 GUI 前台启动」的完整路径**（含窗口服务器往返）。偏差预计在几十毫秒量级，不改变结论。

## 6. 复现命令

```bash
cd spike/s2-coldstart
npm i mysql2 pg ssh2            # C1 需要（测同步 require 的代价）
npm i -D electron-builder        # C3 需要

# 三组各跑 5 次
node run.mjs                     # 或指定 COLD_MODE=C1|C2|C3 RUNS=5
# 结果：raw/summary-C*.json、raw/aggregate.json
```

**环境坑**：本机 shell 泄漏了 `ELECTRON_RUN_AS_NODE=1`，会让 Electron 以纯 Node 模式运行而不创建窗口。必须在 spawn 的 env 里 **`delete env.ELECTRON_RUN_AS_NODE`**（设为空字符串仍会被判为"已设置"）。

---

## 7. 给 PRD / 排期的建议

1. **冷启动预算维持 ≤1500ms，不修正。** 打包版实测 217~265ms，余量充足。
2. **下调懒加载的优先级描述**：评审把它列为"最大的一块/缺一件基本没戏"，实测只值 26ms。建议改为「应做，但属于卫生习惯而非达标关键」。
3. **真正的风险转移到首屏 JS 体积**：建议在工程上给「首屏 JS bundle 体积」设硬预算（建议 ≤1.5MB 未压缩），这比纠结懒加载更能守住 1500ms。
4. **建议按 §5.2(3) 拆子预算**，便于 CI 定位回归（否则 1500ms 超了也不知道是哪一段）。
